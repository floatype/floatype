# floatype 仕様

Apple Silicon の macOS 用の日本語入力です。Mozc の辞書変換を先に出し、小型のニューラルモデル（zenz）が後から補正します。実行時に端末の外へは何も送りません。

- 状態：草案（2026-11-18）。数値の多くは計測で確定させる。
- 土台：Mozc 本体のフォーク（floatype/floatype）。Mozkey はコードを持ち込まず、参考にする。
- 数値の出典：[sources.md](sources.md)

## 1. 前提

| 条件 | 内容 |
| --- | --- |
| ローカル完結 | 推論、学習、計測を含め、実行時に端末の外へ何も送らない |
| 対象 | Apple Silicon の macOS |
| 速さ | 打鍵の表示も変換の応答も、待たされたと感じさせない。打鍵の表示でニューラルの推論を待たない |
| 品質 | 機能の数より完成度を重視する。入れた機能は、計測と試験で品質を確かめてから出す |
| 配布 | OSS |
| 自作しないもの | 変換エンジン（Mozc）、ニューラルモデル（zenz）、推論の実行系（llama.cpp）、辞書（Mozc の辞書が基本。足す語彙の出どころは 9 章） |

## 2. 版ごとの範囲

### 0.1.0（最初に出す版）

必須（【新規】は floatype が作るもの、【拡張】は本家の機能を広げるもの、【引き継ぎ】は本家のまま）：

- **Mozc → zenz の補正**【新規】：Mozc の結果をすぐ出し、zenz の結果で後から差し替える（4章）。
- **状態インジケータ**【新規】：入力中 / Mozc / Zenz… / Zenz の4状態（4章）。
- **ライブ変換**【新規】：Space を押す前から、手が止まったら自動で変換する。本家の Mozc に無い。
- **確定直後の取り消し**【拡張】：本家には、Ctrl+Backspace で確定を取り消して学習も戻す機能がある。floatype は、確定直後の Backspace でも学習を戻すように広げる（文字はアプリが消す）。Escape は含めない。vim や端末では確定の直後に押すのが日常で、含めると確定がまったく学習されなくなる。
- **手動の zenz 補正**【新規】：Ctrl+z（ことえり配列）で zenz の補正を呼ぶ。補正の表示中に Space で Mozc の結果に戻せる。
- **予測候補（サジェスト）**【引き継ぎ＋新規】：打っている途中に、番号なしの小さな一覧で候補を出す。本家で既定オン。窓のちらつきを抑える処理だけを新しく作る（Mozkey の工夫を参考にする）。打鍵の表示の速さの門番は、予測候補の計算を含めて満たす。

あわせて入れる：

- **設定ファイル**：例のファイル（example）を同梱する。型の検査つき。インジケータの色・形・位置も変えられる（5章）。
- **細かい保護規則**：zenz の差し替えで固有名詞や表記を壊さないための規則。計測で足していく（4章）。
- **計測と試験の仕組み**：正答率と速度を大量に測る仕組みと、試験一式（7章）。
- **ローカル完結の試験**（6章）。

### 0.1.0 の後

- 日英混在入力（オプトイン）。オフのときは、インジケータの右端に何も出さない。オンのときは、キャレット直前の語を日本語（あ）と英字（A）のどちらで扱っているかを出す。→ 2026-11-19 に足した（`mixed_english`、既定オフ）。ローマ字がかなにならずに英字が残り、3 文字以上で macOS の英単語一覧（1934 年の Webster's 第 2 版）にある語を英字のままにする。残った英字は変換の問い合わせ（末尾の n は ん になる）で見るので、ten や pan は てん、ぱん のまま。日本語 461 件と、ローマ字が英単語でもある ん で終わる語 405 語で誤判定 0（英字になった 4 語は yin など、yi が かな にならない語）。英単語 58 語で 40 語。一覧に無い新しい語（email など）を足すかは辞書の拡張と同じ判断が要る。
- GUI での設定。Mozc にはすでに設定画面があるので、floatype の項目を足す。→ 2026-11-19 に足した（設定画面の「floatype」のタブ。色と大きさは設定ファイルだけ）。
- 辞書の強化と追加（口語、固有名詞、日付と曜日の語彙）。足す語彙の出どころは 9 章。→ 2026-11-19 に日付と時刻の語を足した。外部のデータではなく数え方の規則から生成した語（`floatype/tools/make_time_words.py`）で、11〜31 日、10〜24 時（20時 は「に従事」とぶつかるので除く）、時半、10〜59 分と、その 時間・分間・日間 の形。曜日と日付の語は Mozc がもともと持ち、誤りは数の読みだけだった。日時と、読みの重なる語（十字架、虹、従事 など）の 50 件で 16 → 43 正解（前に正しかったものは全部そのまま）、AJIMEE と回帰セットは変わらず。生成した語を出どころとして認めるかは 9 章の判断に含める。口語と固有名詞はまだ（外部のデータが要る）。
- zenz を待ってから表示する方式：ライブ変換で、Mozc の結果を先に出さず、zenz の結果を待ってから表示する。→ 2026-11-19 に足した（`live_conversion_waits_for_zenz_millisec`、既定 0＝待たない）。待っている間は打った文字のまま見せ、キーが来たら隠れた変換をやめてから普通に処理する（Enter は見えている読みを確定、Space は普段どおり変換）。ライブ変換の再生で、正答率は同じまま、手を止めた間の画面の変化が約 25% 減った。
- zenz の学習：補正の採用と却下を記録し、次から再利用する。表示中の補正を Ctrl+Delete で止めて記憶する操作も含む（本家の Ctrl+Delete は予測候補の削除なので、補正の表示中だけ効く割り当てにする）。→ 2026-11-19 に足した。却下：Ctrl+Delete で止めた「読みと zenz の答え」を覚えて繰り返さない。採用：zenz の補正をそのまま確定したら覚え、次に同じ読みでは zenz を待たずにすぐ出す（zenz はそのあとも答えを出し、文脈で違えば差し替わる）。Space で戻してから確定したものは覚えない。`zenz_learning` で切れ、ユーザー履歴の消去で両方忘れる。
- 入力の小技：句読点の単打確定、曖昧なローマ字の途中表示、1つのキーに複数のコマンドを割り当てる。→ 2026-11-19 に句読点の単打確定を足した（`direct_commit_characters`、既定は空＝使わない）。打つとその場で変換して zenz の答え（か打ち切り）を待ってから確定する。待っている間の Enter は確定だけ、ほかのキーは見えているものを確定してから効く。1 つのキーに複数のコマンドも足した。キー設定の表でコマンドを `Commit|IMEOff` のように `|` でつなぐと順に実行し、2 つ目以降はその時点の状態で解決する。設定画面のキー設定エディタは連続の行を表に出さずに保つ（組み立てる UI は無い）。曖昧なローマ字の途中表示も足した（`display_ambiguous_romaji`、既定オフ）。長い規則の途中のローマ字を、いまの時点の かな で見せる（n は ん、ms→ます と mst→ました があれば ms は ます）。長い規則が成り立たなければ見えていた かな のまま続き、カーソルが中に入ると（Backspace など）その かな で確定してから編集する。
- 候補の窓とライブ変換のルビの外観の設定。→ 2026-11-19 に候補の窓の文字の大きさ（`candidate_font_scale_percent`）と色（`candidate_style`）を足した。ライブ変換のルビ（読みを上に小さく添える表示、`live_conversion_ruby`、既定オフ）も足した。ルビの色と大きさの設定、縦書きでのルビはまだ。
- 縦書き：候補やルビを、縦書きの入力先に合わせて配置する。→ 2026-11-19 にインジケータを縦書きの列の右に出すようにした（判定は Mozc の候補窓と同じ）。候補の窓の縦書きの配置は Mozc がもともと持つ。

### Mozkey 由来の機能の振り分け

Mozkey にある8機能を入れることにした。どの版に入れるかは、実装の都合で次のように決めた。今の仕組みにそのまま乗るものと、門番を満たすのに要るものを 0.1.0 に入れ、保存先や専用の規則が増えるものを後に回した。

| 機能 | 版 | 理由 |
| --- | --- | --- |
| 手動の zenz 補正 | 0.1.0 | キー操作で同じ依頼の流れを呼ぶだけ。補正の表示中に Space で Mozc の結果に戻せる（戻しても記憶しない） |
| 細かい保護規則 | 0.1.0 から | 正答率の門番を満たすのに要る。0.1.0 から入れ、計測で Mozkey 並みまで足していく |
| インジケータの外観 | 0.1.0 | インジケータも設定ファイルも 0.1.0 で作るので、色・形・位置の項目を最初から持たせる。ルビを基準にした位置は除く |
| zenz を待ってから表示 | 0.1.0 の後 | 専用の規則と、2方式ぶんのタイミングの試験が要る |
| zenz の学習（Ctrl+Delete で止めて記憶する操作を含む） | 0.1.0 の後 | 保存先と、学習を消す手段が要る。学習が入ると計測の結果が履歴に左右されるので、まず学習なしで基準を測る |
| 辞書の拡張 | 0.1.0 の後 | データの作業で、語彙の出どころとライセンスの確認が先に要る |
| 入力の小技 | 0.1.0 の後 | 本家の入力処理とキー設定に手が入り、zenz の流れと関係が無い |
| 候補の窓とルビの外観 | 0.1.0 の後 | 本家の候補表示に手が入る |
| 縦書き | 0.1.0 の後 | 候補表示の配置の作り替えが要る |

### 門番

各版は、次を1つも破らずに出す。

| 門番 | 条件 |
| --- | --- |
| 速さ | IME が打鍵の表示に足す遅延が p50 5ms 以下、p99 16.7ms 以下。Space から Mozc の結果が出るまでも同じ |
| 軽さ | 常駐メモリは合計 250MB 以下（暫定）。入力していない間の CPU 起床は 0 回/秒 |
| 正答率 | 評価セットで Mozc 単体より正答率が高い。前の版より下がらない |
| ローカル完結 | 通信を拒否した環境で全機能が動き、通信の試みが 0 件 |

## 3. やらないこと

次の機能は入れない。どれも Mozkey にも無い。

| 機能 | 入れない理由 |
| --- | --- |
| 文章の生成、書き換え、校正 | 打った読みと違う文を出す機能は範囲外 |
| 打鍵の打ち間違いの自動補正 | Mozc の変換器の作り替えが要る |
| 音声入力 | 認識モデルの常駐が 0.7GB 以上 |
| OS 内蔵の言語モデル | 変換の正解率が低く、応答は最短でも約 320ms |
| Neural Engine での推論 | OS 更新のたびにキャッシュが無効になる |
| クラウド同期、自動更新、利用統計 | ローカル完結に反する |

## 4. 動作の規則

### 変換の流れ

1. 打っている間は、Mozc がかなと予測候補を表示する。インジケータは「入力中」。
2. Space を押したとき、またはライブ変換（既定でオン）で手が止まったとき（待ち時間と最小文字数は設定できる）に、Mozc が変換して結果をすぐ出す。インジケータは「Mozc」。
3. zenz を始める条件（Space のときはすぐ、ライブ変換では設定した待ち時間の後）を満たしたら、読みと前後の文脈を採点プロセスへ送る。インジケータは「Zenz…」。
4. zenz の結果が辞書と違い、差し替えの条件を満たせば、表示を1回だけ差し替える。インジケータは「Zenz」。
5. 結果が辞書と同じとき、条件を満たさず捨てたとき、打ち切り時間（設定できる。5章）までに届かなかったときは、辞書の結果のまま。インジケータは「Mozc」に戻る。

- **文脈**：入力先アプリの前後の文字を使う（Mozc 本体にすでに取得の処理がある）。取れないアプリでは、Mozc の履歴文節（直前に確定した文節）を使う。

### 状態インジケータ

![状態インジケータの遷移と、日英混在オンのときの表示](indicator.png)

- 状態は、いま見えている変換結果が辞書と zenz のどちらのものかを示す。補正が無かったときに「Zenz」と出さない。
- 図に無い遷移：手動の zenz 補正では「Mozc → Zenz…」に進む。補正の表示中に Space で Mozc に戻すと「Zenz → Mozc」になる。
- 既定の色は Mozkey の既定色にそろえる。形・色・位置は外観の設定で変えられるようにする（2章）。キャレットの位置が取れない入力先では、画面下部の決まった位置に出す。

### 差し替えの規則

- 自動の差し替えは、1つの変換につき1回だけ。ライブ変換では、手が止まるたびに新しい変換になる。
- 手動の zenz 補正は利用者の操作なので、自動の差し替えの後でも行える。補正の表示中に Space を押すと Mozc の結果に戻る。
- 依頼の後に利用者が何か操作したら、届いた結果は捨てる。依頼には通し番号を付け、最新の番号の結果だけを使う。
- 利用者が選び直した文節は差し替えない。Mozc の学習で先頭になった候補も差し替えない。
- 読みが入力と食い違う結果は捨てる。zenz が読みをかなのまま返した結果も捨てる（回帰セットで害が 20 から 10 に減った）。
- 数字、英字、記号、絵文字が辞書の結果と違う場合に捨てる規則は、計測で逆効果だったので入れない。数字と英字は AJIMEE-Bench で正しい補正（３年９月１５日、ＭＩ６）を止め、82.0% が 81.0% に下がった。記号と絵文字は害を減らさず 81.5% に下がった。全角・半角の違いは、候補への対応づけで Mozc の幅を残す。
- 規則は Mozkey 並みを目標に、計測で効果を確かめながら足していく。Mozkey の採用条件（固有名詞の保護、記号の表記の復元など）を候補一覧として使う。計測は `floatype/eval/regression.py`（Mozc の回帰セット 308 件）と `floatype/eval/ajimee.py --engine replay`（AJIMEE-Bench 200 件）。試して入れなかった規則とその数字は `ZenzCorrector::Poll` のコメントにある（かなと漢字の書き換え、数字・英字・記号、zenz の確信度）。
- Enter で確定されるのは、その時点で見えているものだけにする。
- secure input 中は zenz に送らない。

## 5. 設定

- **ファイル**：Mozc の設定定義（`config.proto`）をそのまま型の定義にして、protobuf のテキスト形式で書く。floatype の項目も同じ定義に足す。
- **型の検査**：読み込み時に protobuf が型と項目名を検査する。誤りがあれば、どの行が悪いかを通知し、前の正しい設定のまま動く。
- **値の範囲の検査**：protobuf は型しか検査しないので、時間や文字数は読み込み時に範囲も検査する。範囲外なら型の誤りと同じ扱いにする。
- **例のファイル**：全項目と既定値と説明を書いた `config.example.txtpb` を同梱する。設定ファイルは dotfiles としてコード管理できる。
- **正本**：テキストの設定ファイル（`~/.config/floatype/config.txtpb`）に書いた項目は、設定画面より優先する。書かない項目は設定画面（保存先は `config1.db`）が決める。floatype はファイルを書き換えない（書き出すとコメントと順番が消え、dotfiles を壊すため）。ファイルの値は `config1.db` に紛れ込まないので、行を消せば設定画面の値に戻る。保存して 1 秒ほどで反映する。
- **GUI**：0.1.0 の後。GUI で変えた内容も同じファイルに書き出すので、両方の手段が食い違わない。

| zenz を打ち切るまでの時間 | 300ms（暫定） | 50〜5000ms |
| 予測候補（サジェスト）のオン・オフ | オン | — |

## 6. 構成

### Mozkey との比較

| 項目 | Mozkey（macOS） | floatype |
| --- | --- | --- |
| プロセス | IME 本体 → Mozc 変換 → 採点 → llama-server の4つ | IME 本体 → Mozc 変換 → 採点の3つ。採点プロセスが推論も行う |
| 受け渡し | Unix ソケット + HTTP（127.0.0.1） | Unix ソケットだけ |
| zenz を呼ぶ時機 | ライブ変換中に手が 700ms 止まったとき、または手動のキー操作 | Space を押したときはすぐ。ライブ変換中は手が止まって設定した待ち時間の後。手動のキー操作でも呼べる |
| 表示 | Mozc を先に出す（既定）。zenz を最大 250ms 待つ方式も選べる | Mozc を先に出す方式。待つ方式は 0.1.0 の後 |
| 文脈 | アプリの前後の文字 | 同じ。取れないときは Mozc の履歴文節 |
| Mozc との距離 | 大きく改造（`session.cc` が約4倍、582 ファイルに差分） | 自前のコードは別ディレクトリに置き、本体の変更は接点にとどめる（目標。9章） |
| インジケータ | 4状態。形や色や位置を細かく変えられる | 4状態。日英混在がオンのときだけ右端に あ / A。色・形・位置は設定で変えられる |

推論を Mozc の変換プロセスに入れないのは、推論が異常終了すると未確定の文字ごと消えるためで、これは Mozkey と同じ考え方。

| `session/session.cc` | 予測候補：ちらつきを抑えるための更新の保留 |
| `session/session.cc` | 手動の zenz 補正：補正を呼ぶコマンドと、Space で Mozc に戻す処理 |
| `data/keymap/` | 手動の zenz 補正と、Mozc に戻す操作のキー割り当て |
| `mac/mozc_imk_input_controller.mm` | 結果を受け取りに行くタイマー（今の Mozc は遅延指定を無視する） |
| `protocol/commands.proto`、`config.proto` | インジケータの状態と設定の項目を足す |
| `renderer/mac/` | インジケータの窓を登録する（窓そのものは新しいファイル） |
| ビルドと配布の設定 | 採点プロセスとモデルを同梱する |

- 触った本体ファイルの数と行数を CI で出し、増え方を見張る。
- どの変更も、本体側は自前のモジュールを呼ぶだけにする。Mozkey で `session.cc` が膨らんだのは、まさにこれらの部分。
- `master` は本家 google/mozc の写しとして追従させ、floatype の変更は `main` に積む。同期は `gh repo sync floatype/floatype --branch master` で行う（既定ブランチは `main` なので、`--branch master` を省くと `main` が対象になる）。

### ローカル完結

- **通信するコードを持たない**：OSS 版の Mozc には、利用統計、更新確認、クラッシュ送信のどれもない（確認済み）。ブラウザで URL を開く経路はあるが、本家にはその URL に値を入れるコードが無い。floatype が足すのはプロセス間の Unix ソケットだけで、TCP は使わない。
- **llama.cpp**：推論のライブラリだけをリンクし、モデルを取得するコードは入れない。モデルは配布物に同梱する。
- **試験**：CI で全プロセスをネットワーク拒否の sandbox プロファイルの下で動かし、打鍵再生を流す。通信の試みが 0 件で、全機能が動くことを確かめる。
- **OS による遮断**：目標とし、方式は計測の段階で決める（9章）。
- **secure input**：`/Library/Input Methods` に入れる（`~/Library` 側の IME は secure input 中に使えない）。

## 7. 計測と試験

改善は「大量に測る → 失敗を分類する → 直す → 測り直す」の繰り返しで進める。感覚で直さない。

### 正答率

- **評価セット**：公開の評価セット（AJIMEE-Bench の 200 問と、その個人による拡張版の 628 問）に加え、数千文規模の自前のセットを作る。同音語、数字、固有名詞、カタカナ語、文脈で決まる語などの種類ごとに集計する。
- **比べる相手**：Mozc 単体、前の版、floatype 自身の設定違い（文脈の長さ、モデル、待ち時間、打ち切り時間）。
- **測り方**：正答率は2通りで出す。1つは zenz の完了を待った場合（モデルの上限）、もう1つは打鍵再生の間隔どおりに確定した場合（利用者が実際に得る結果）。2章の門番は後者で判定する。
- **頻度**：変更のたびに CI で回す。正答率が前の版より下がる変更は入れない。
- **失敗の記録**：zenz が辞書を悪くした例と、良くした例を両方とも残し、規則の見直しに使う。

### 速さ

- 打鍵の列を再生して、打鍵の表示、Space の応答、zenz の応答の分布を測る。速い打鍵者の打鍵間隔も再生する。
- 差し替えが効いた割合（利用者の次の操作より前に差し替わった割合）を測る。

### 道具と、0.1.0 時点の数字（2026-11-19、M4 Pro、CPU 4 スレッド）

- `floatype/eval/ajimee.py --engine replay`：Space で変換する流れを、本物の Mozc と採点プロセスで再生する。AJIMEE 200 問で Mozc 単独 51.5%、zenz の補正後 82.0%。Space の応答 中央値 1.2ms・99% 6.6ms。
- `floatype/eval/ajimee.py --engine live`：1 キーずつ打ってライブ変換で確定する流れ。キーで打てる 159 問で Space と同じ 134 正解。`--pause_every` で手を止める間隔を変えられる。4 文字ごとに止めると、前の表示を固定する既定は 133・MinCER 0.0290、変換し直す設定は 134・0.0232。
- `floatype/eval/regression.py`：Mozc の回帰セット 308 件で zenz の勝ちと害を数える。Mozc 単独 218、補正後 255、害 9。
- `floatype/eval/local_only.py`：ネットワークに触れたら殺す囲いの中で変換し、全実行ファイルのネットワーク関数を調べる（6 章）。
- 速くする工夫：採点プロセスに Mozc の結果を下書きとして渡し、1 回の計算で確かめる（投機的デコード、中央値 −17%）。前の依頼と先頭が同じプロンプトは計算し直さない（ライブ変換の流れで最後の依頼の中央値 20.4→11.2ms）。変換プロセスは 10ms ごとに結果を取りに行き、画面が変わらない呼び戻しはアプリに送らない。

### 試験

- 自前のモジュールの単体試験。
- 打鍵再生による結合試験。差し替えの規則と、インジケータの遷移を確かめる。手動の zenz 補正と、Space で Mozc に戻す操作も含める。
- タイミングの試験。Mozkey で報告された不具合（未表示の結果の確定、古い結果の採用、表示と確定内容の食い違い）を再現する試験から書く。
- 主要アプリでの動作確認（ブラウザ、エディタ、ターミナル、チャット）。

## 8. 0.1.0 までの順番

1. Mozc を macOS でビルドする。
2. 打鍵再生と正答率の計測の仕組みを作り、Mozc 単体の数値を取る。
3. 採点プロセス（llama.cpp + zenz）を作り、Space で依頼して1回差し替える最小の形を動かす。
4. ライブ変換、予測候補、確定直後の取り消し、手動の zenz 補正、差し替えの規則と保護規則、インジケータとその外観を入れ、計測と改善を繰り返す。
5. 設定ファイル、ローカル完結の試験、署名と配布を整えて 0.1.0 を出す。

## 9. まだ分かっていないこと

| 分からないこと | なぜ大事か | だめだった場合 |
| --- | --- | --- |
| zenz の応答時間と電力（この用途の公開の実測が無い） | 遅いと差し替えが間に合わない | 小さいモデルにする |
| 差し替えが次の操作より前に間に合う割合 | 低いと zenz を入れた意味が薄い | 打っている間に先に計算を始める |
| 採点プロセスから GPU を使えるか | 速度の見積もりは GPU の値 | CPU で動く小さいモデルにする |
| zenz の重みのライセンス（2026-11-07 に表記が変わった） | 同梱できるかが決まる | 別のモデルにする |
| タイマーで、キー操作の外から表示を差し替えても安全か | 安全でないと表示が壊れる | 差し替えず、次の候補の先頭に置く |
| 予測候補とライブ変換を両方オンにしても、速さの門番を満たせるか | 既定の状態で速さを保証できるか | 予測候補の計算を軽くする（候補数の上限など） |
| ライブ変換、確定直後の取り消し、予測候補の抑制を足しても、本体の変更を接点に保てるか | 本家の更新の取り込みやすさが決まる | 膨らんだ箇所と行数を記録し、取り込みの手間を測りながら進める |
| Mozc の既存の設定画面（`config1.db` に保存）とテキストの設定ファイルの関係 | 保存先が2つあると食い違う | 決めた：ファイルに書いた項目はファイルが勝ち、残りは設定画面が決める（5 章）。設定画面でファイルの項目を変えても、ファイルの値に戻る |
| 辞書の拡張で足す語彙の出どころ（既存の公開データ、Mozkey のデータ、手作り）とライセンス | 再配布できるかが決まる。Mozkey のデータを使う場合は、コードを持ち込まない方針との関係も決める | 出どころとライセンスがはっきりした公開データだけを使う |
| OS による通信の遮断の方式（Mozc は LaunchAgent で常駐し、サンドボックスを使っていない） | 「通信しない」を OS に保証させられるか | 試験で通信しないことを確かめるだけにする |
