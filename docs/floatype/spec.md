# floatype 仕様

Apple Silicon の macOS 用の日本語入力です。Mozc の辞書変換を先に出し、小型のニューラルモデル（zenz）が後から補正します。実行時に端末の外へは何も送りません。

- 状態：草案（2026-11-18）。数値の多くは計測で確定させる。
- 実際の動き（打鍵から確定までの時間の流れ、インジケータ、予測候補、zenz の採点プロセス）は [behavior.md](behavior.md) にまとめる。
- 土台：Mozc 本体のフォーク（floatype/floatype）。Mozkey はコードを持ち込まず、参考にする。
- 数値の出典：[sources.md](sources.md)

## 2. 版ごとの範囲

### 0.1.0（最初に出す版）

必須（【新規】は floatype が作るもの、【拡張】は本家の機能を広げるもの、【引き継ぎ】は本家のまま）：

- **Mozc → zenz の補正**【新規】：Mozc の結果をすぐ出し、zenz の結果で後から差し替える（4章）。
- **状態インジケータ**【新規】：入力中 / Mozc / Zenz… / Zenz の4状態（4章）。
- **ライブ変換**【新規】：Space を押す前から、手が止まったら自動で変換する。本家の Mozc に無い。
- **確定直後の取り消し**【拡張】：本家には、Ctrl+Backspace で確定を取り消して学習も戻す機能がある。floatype は、確定直後の Backspace でも学習を戻すように広げる（文字はアプリが消す）。Escape は含めない。vim や端末では確定の直後に押すのが日常で、含めると確定がまったく学習されなくなる。
- **手動の zenz 補正**【新規】：Ctrl+z（ことえり配列）で zenz の補正を呼ぶ。補正の表示中に Space で Mozc の結果に戻せる。
- **予測候補（サジェスト）**【引き継ぎ＋新規】：打っている途中に、番号なしの小さな一覧で候補を出す。本家で既定オン。窓のちらつきを抑える処理だけを新しく作る（Mozkey の工夫を参考にする）。打鍵の表示の速さの門番は、予測候補の計算を含めて満たす。

あわせて入れる：

- **設定ファイル**：例のファイル（example）を同梱する。型の検査つき。インジケータの色・形・位置も変えられる（5章）。
- **細かい保護規則**：zenz の差し替えで固有名詞や表記を壊さないための規則。計測で足していく（4章）。
- **計測と試験の仕組み**：正答率と速度を大量に測る仕組みと、試験一式（7章）。
- **ローカル完結の試験**（6章）。

- zenz の学習：補正の採用と却下を記録し、次から再利用する。表示中の補正を Ctrl+Delete で止めて記憶する操作も含む（本家の Ctrl+Delete は予測候補の削除なので、補正の表示中だけ効く割り当てにする）。→ 2026-11-19 に足した。却下：Ctrl+Delete で止めた「読みと zenz の答え」を覚えて繰り返さない。採用：zenz の補正をそのまま確定したら覚え、次に同じ読みでは zenz を待たずにすぐ出す（zenz はそのあとも答えを出し、文脈で違えば差し替わる）。Space で戻してから確定したものは覚えない。`zenz_learning` で切れ、ユーザー履歴の消去で両方忘れる。
- 入力の小技：句読点の単打確定、曖昧なローマ字の途中表示、1つのキーに複数のコマンドを割り当てる。→ 2026-11-19 に句読点の単打確定を足した（`use_direct_commit`、既定オフ。文字は `direct_commit_characters`、既定は Mozkey と同じ 、。？！「」）。設定画面は Mozkey と同じく、全体のオン・オフと 。、？！（）「」・ のチェックボックスで選ぶ。打つとその場で変換して zenz の答え（か打ち切り）を待ってから確定する。待っている間の Enter は確定だけ、ほかのキーは見えているものを確定してから効く。1 つのキーに複数のコマンドも足した。キー設定の表でコマンドを `Commit|IMEOff` のように `|` でつなぐと順に実行し、2 つ目以降はその時点の状態で解決する。設定画面のキー設定エディタは連続の行を表に出さずに保つ（組み立てる UI は無い）。曖昧なローマ字の途中表示も足した（`display_ambiguous_romaji`、既定オフ）。長い規則の途中のローマ字を、いまの時点の かな で見せる（n は ん、ms→ます と mst→ました があれば ms は ます）。長い規則が成り立たなければ見えていた かな のまま続き、カーソルが中に入ると（Backspace など）その かな で確定してから編集する。
- 候補の窓とライブ変換のルビの外観の設定。→ 2026-11-19 に候補の窓の文字の大きさ（`candidate_font_scale_percent`）と色（`candidate_style`）を足した。ライブ変換のルビ（読みを上に小さく添える表示、`live_conversion_ruby`、既定オフ）も足した。ルビの大きさと色（`ruby_style`、設定ファイルだけ）と、縦書きでのルビ（列の右、インジケータがあればその右。文字は横書きのまま）も足した。
- 縦書き：候補やルビを、縦書きの入力先に合わせて配置する。→ 2026-11-19 にインジケータを縦書きの列の右に出すようにした（判定は Mozc の候補窓と同じ）。候補の窓の縦書きの配置は Mozc がもともと持つ。

### Mozkey 由来の機能の振り分け

Mozkey にある8機能を入れることにした。どの版に入れるかは、実装の都合で次のように決めた。今の仕組みにそのまま乗るものと、門番を満たすのに要るものを 0.1.0 に入れ、保存先や専用の規則が増えるものを後に回した。

| 機能 | 版 | 理由 |
| --- | --- | --- |
| 手動の zenz 補正 | 0.1.0 | キー操作で同じ依頼の流れを呼ぶだけ。補正の表示中に Space で Mozc の結果に戻せる（戻しても記憶しない） |
| 細かい保護規則 | 0.1.0 から | 正答率の門番を満たすのに要る。0.1.0 から入れ、計測で Mozkey 並みまで足していく |
| インジケータの外観 | 0.1.0 | インジケータも設定ファイルも 0.1.0 で作るので、色・形・位置の項目を最初から持たせる。ルビを基準にした位置は除く |
| zenz を待ってから表示 | 0.1.0 の後 | 専用の規則と、2方式ぶんのタイミングの試験が要る |
| zenz の学習（Ctrl+Delete で止めて記憶する操作を含む） | 0.1.0 の後 | 保存先と、学習を消す手段が要る。学習が入ると計測の結果が履歴に左右されるので、まず学習なしで基準を測る |
| 配布用のインストーラ（GitHub の Releases に .pkg を置く） | 0.1.0 の後 | 2026-11-19 にワークフロー（`.github/workflows/release.yml`）を作った。Apple Silicon 用の pkg を作り、`v*` のタグで Release の下書きに SHA-256 と一緒に付ける。手動実行は成果物だけ。版の番号は floatype の版に元の Mozc の版を添えた `0.1.0+mozc.3.35.6354`（`version.bzl` の FLOATYPE_*）で、pkg の名前、「Floatype について」、Finder の説明に出る。アプリの版の欄は Apple の決まりで数字 3 つなので `0.1.0`、中の版（CFBundleVersion）は Mozc の `3.35.6354.101` のまま（プロセスどうしの照合に使う）。版の欄が以前の 3.35 より小さくなるので、pkg は版を比べずに上書きする。画面に出る名前は Floatype（F は大文字。2026-11-19）、アプリやプロセスのファイル名、バンドル ID、設定の置き場所などの識別子は小文字の floatype のまま |
| 辞書の拡張 | 0.1.0 の後 | データの作業で、語彙の出どころとライセンスの確認が先に要る |
| 入力の小技 | 0.1.0 の後 | 本家の入力処理とキー設定に手が入り、zenz の流れと関係が無い |
| 候補の窓とルビの外観 | 0.1.0 の後 | 本家の候補表示に手が入る |
| 縦書き | 0.1.0 の後 | 候補表示の配置の作り替えが要る |

### 門番

各版は、次を1つも破らずに出す。

| 門番 | 条件 |
| --- | --- |
| 速さ | IME が打鍵の表示に足す遅延が p50 5ms 以下、p99 16.7ms 以下。Space から Mozc の結果が出るまでも同じ |
| 軽さ | 常駐メモリは合計 250MB 以下（暫定）。入力していない間の CPU 起床は 0 回/秒 |
| 正答率 | 評価セットで Mozc 単体より正答率が高い。前の版より下がらない |
| ローカル完結 | 通信を拒否した環境で全機能が動き、通信の試みが 0 件 |

## 3. やらないこと

次の機能は入れない。どれも Mozkey にも無い。

| 機能 | 入れない理由 |
| --- | --- |
| 文章の生成、書き換え、校正 | 打った読みと違う文を出す機能は範囲外 |
| 打鍵の打ち間違いの自動補正 | Mozc の変換器の作り替えが要る |
| 音声入力 | 認識モデルの常駐が 0.7GB 以上 |
| OS 内蔵の言語モデル | 変換の正解率が低く、応答は最短でも約 320ms |
| Neural Engine での推論 | OS 更新のたびにキャッシュが無効になる |
| クラウド同期、自動更新、利用統計 | ローカル完結に反する |

## 4. 動作の規則

### 変換の流れ

1. 打っている間は、Mozc がかなと予測候補を表示する。インジケータは「入力中」。
2. Space を押したとき、またはライブ変換（既定でオン）で手が止まったとき（待ち時間と最小文字数は設定できる）に、Mozc が変換して結果をすぐ出す。インジケータは「Mozc」。
3. zenz を始める条件（Space のときはすぐ、ライブ変換では設定した待ち時間の後）を満たしたら、読みと前後の文脈を採点プロセスへ送る。インジケータは「Zenz…」。
4. zenz の結果が辞書と違い、差し替えの条件を満たせば、表示を1回だけ差し替える。インジケータは「Zenz」。
5. 結果が辞書と同じとき、条件を満たさず捨てたとき、打ち切り時間（設定できる。5章）までに届かなかったときは、辞書の結果のまま。インジケータは「Mozc」に戻る。

- **文脈**：入力先アプリの前後の文字を使う（Mozc 本体にすでに取得の処理がある）。取れないアプリでは、Mozc の履歴文節（直前に確定した文節）を使う。

### 状態インジケータ

![状態インジケータの遷移と、日英混在オンのときの表示](indicator.png)

- 状態は、いま見えている変換結果が辞書と zenz のどちらのものかを示す。補正が無かったときに「Zenz」と出さない。
- 図に無い遷移：手動の zenz 補正では「Mozc → Zenz…」に進む。補正の表示中に Space で Mozc に戻すと「Zenz → Mozc」になる。
- 既定の色は Mozkey の既定色にそろえる。形・色・位置は外観の設定で変えられるようにする（2章）。キャレットの位置が取れない入力先では、画面下部の決まった位置に出す。

### 差し替えの規則

- 自動の差し替えは、1つの変換につき1回だけ。ライブ変換では、手が止まるたびに新しい変換になる。
- 手動の zenz 補正は利用者の操作なので、自動の差し替えの後でも行える。補正の表示中に Space を押すと Mozc の結果に戻る。
- 依頼の後に利用者が何か操作したら、届いた結果は捨てる。依頼には通し番号を付け、最新の番号の結果だけを使う。
- 利用者が選び直した文節は差し替えない。Mozc の学習で先頭になった候補も差し替えない。
- 読みが入力と食い違う結果は捨てる。前に文が無いときは、zenz が読みをかなのまま返した結果も捨てる（回帰セットで害が 20 から 10 に減った。守られた害はどれも前に文の無い短い読みだった：いく→行く、けいさん→計算）。前に文があり、答えが全部ひらがなで、Mozc の結果が読み全体に対する辞書の 1 語でなければ採用する（そうなの の なの、いただけますと の けますと。2026-11-20）。実際のアプリではほぼいつも前に文がある（アプリが教えなければ直前に確定した文を使う）ので、回帰セットと Anthy の読みに前の文（「それで、」「昨日の話だけど、」）を付けて確かめた：前に文があれば何でも採用すると かな の答えが 9〜12 件出て、害が 7〜9 件（馬運車→バウンシャ、愛新覚羅→アイシンカクラ、計算→けいさん、持つ→もつ）、勝ちが 5 件。今の条件では 2〜5 件に減り、害は表記の 2 件（分かりづらく→わかりづらく、脅かし→おどかし）、勝ちは 1 件。
- Mozc の文節のままでは候補で書けない結果は、文節を区切り直して Mozc に変換し直させ、それでも書けるときだけ差し替える（動きの細部は behavior.md 1 章）。漢数字に細かく区切られた数（線|九百|七|重|二）は、各文節の漢数字の候補をつなげた数（千九百七十二）が zenz の数字と合えば一つの文節にまとめ、数字を候補に足す。Space で Mozc の元の区切りと結果に戻る。
- 利用者が打った数字と英字（読みに入っている 2026、gpt-5 など）を、Mozc の結果にあるのに zenz が変えた結果は捨てる（Mozkey と同じ。Mozc が落とした数字を zenz が戻すのは認める）。かなから zenz が書いた数字（さんがつ→３月）は zenz に任せる。数字、英字、記号、絵文字が辞書の結果と違えばすべて捨てる規則は、正しい補正（３年９月１５日、ＭＩ６）を止めて AJIMEE-Bench が 82.0% から 81.0% に下がったので入れない。全角・半角の違いは、候補への対応づけで Mozc の幅を残す。
- 規則は Mozkey 並みを目標に、計測で効果を確かめながら足していく。Mozkey の採用条件（固有名詞の保護、記号の表記の復元など）を候補一覧として使う。計測は `floatype/eval/regression.py`（Mozc の回帰セット 308 件）と `floatype/eval/ajimee.py --engine replay`（AJIMEE-Bench 200 件）。試して入れなかった規則とその数字は `ZenzCorrector::Poll` のコメントにある（かなと漢字の書き換え、数字・英字・記号、zenz の確信度）。
- Enter で確定されるのは、その時点で見えているものだけにする。
- secure input 中は zenz に送らない。

## 5. 設定

- **ファイル**：Mozc の設定定義（`config.proto`）をそのまま型の定義にして、TOML で書く（キーは項目名）。floatype の項目も同じ定義に足す。
- **型の検査**：読み込み時に型と項目名を検査する。誤りがあれば、どの行が悪いかを通知し、前の正しい設定のまま動く。
- **値の範囲の検査**：型だけでは足りないので、時間や文字数は読み込み時に範囲も検査する。範囲外なら型の誤りと同じ扱いにする。
- **例のファイル**：全項目と既定値と説明を書いた `config.example.toml` を同梱する。設定ファイルは dotfiles としてコード管理できる。
- **正本**：設定ファイル（`~/.config/floatype/config.toml`）だけが正本。Mozc の項目も floatype の項目もここに書き、書かない項目は既定値。手で書き換えると、保存して 1 秒ほどで反映する。`config1.db` は最後に読めた設定の写しで、ファイルが壊れたまま起動したときに使う。
- **GUI**：設定画面は入力の手段で、変えた項目の行だけをこのファイルに書き込む。コメント、空行、順番は残すので、dotfiles を壊さない。ファイルが壊れている間は書き込まず、通知で知らせる。
- **移行**：ファイルが無いときは、`config1.db` と、前の版の `config.txtpb`（あれば）を合わせて、既定と違う項目だけを書いたファイルを作る。`config1.db` と `config.txtpb` は消さない。

### 主な設定項目

時間の既定値は暫定で、計測して決める。Mozkey の既定値を出発点にする。

| 項目 | 既定値 | 範囲 |
| --- | --- | --- |
| ライブ変換のオン・オフ | オン（Mozkey の既定はオフ） | — |
| ライブ変換を始めるまでの待ち時間 | 228ms（Mozkey と同じ） | 0〜2000ms |
| ライブ変換を始める最小の文字数 | 2文字（Mozkey と同じ） | 1〜10 |
| zenz の補正のオン・オフ | オン | — |
| zenz を始めるまでの待ち時間（ライブ変換中、最後のキーから） | 500ms（Mozkey は 700ms） | 0〜5000ms |
| zenz を打ち切るまでの時間 | 300ms（暫定） | 50〜5000ms |
| 予測候補（サジェスト）のオン・オフ | オン | — |
| 足した辞書の語を予測候補に出す | 出さない（Mozkey は出す） | — |
| 状態インジケータの表示 | オン | — |
| 日英混在入力のオン・オフ | オフ | — |
| インジケータの色・形・位置 | Mozkey の既定色。未確定文字の近く | 位置は未確定文字の上・下・横から選ぶ |
| 手動の zenz 補正のキー | Ctrl+z（ことえり配列。キー設定の ZenzCorrect で変えられる） | — |

### Mozkey との比較

| 項目 | Mozkey（macOS） | floatype |

| `protocol/commands.proto`、`config.proto` | インジケータの状態と設定の項目を足す |
| `renderer/mac/` | インジケータの窓を登録する（窓そのものは新しいファイル） |
| ビルドと配布の設定 | 採点プロセスとモデルを同梱する |

- 触った本体ファイルの数と行数を CI で出し、増え方を見張る。
- どの変更も、本体側は自前のモジュールを呼ぶだけにする。Mozkey で `session.cc` が膨らんだのは、まさにこれらの部分。
- `master` は本家 google/mozc の写しとして追従させ、floatype の変更は `main` に積む。同期は `gh repo sync floatype/floatype --branch master` で行う（既定ブランチは `main` なので、`--branch master` を省くと `main` が対象になる）。

### ローカル完結

- **通信するコードを持たない**：OSS 版の Mozc には、利用統計、更新確認、クラッシュ送信のどれもない（確認済み）。ブラウザで URL を開く経路はあるが、本家にはその URL に値を入れるコードが無い。floatype が足すのはプロセス間の Unix ソケットだけで、TCP は使わない。
- **llama.cpp**：推論のライブラリだけをリンクし、モデルを取得するコードは入れない。モデルは配布物に同梱する。
- **試験**：CI で全プロセスをネットワーク拒否の sandbox プロファイルの下で動かし、打鍵再生を流す。通信の試みが 0 件で、全機能が動くことを確かめる。
- **OS による遮断**：目標とし、方式は計測の段階で決める（9章）。
- **secure input**：`/Library/Input Methods` に入れる（`~/Library` 側の IME は secure input 中に使えない）。

## 7. 計測と試験

改善は「大量に測る → 失敗を分類する → 直す → 測り直す」の繰り返しで進める。感覚で直さない。

### 正答率

- **評価セット**：公開の評価セット（AJIMEE-Bench の 200 問と、その個人による拡張版の 628 問、Anthy のコーパスの 1,745 文）に加え、数千文規模の自前のセットを作る。同音語、数字、固有名詞、カタカナ語、文脈で決まる語などの種類ごとに集計する。
- **比べる相手**：Mozc 単体、前の版、floatype 自身の設定違い（文脈の長さ、モデル、待ち時間、打ち切り時間）。
- **測り方**：正答率は2通りで出す。1つは zenz の完了を待った場合（モデルの上限）、もう1つは打鍵再生の間隔どおりに確定した場合（利用者が実際に得る結果）。2章の門番は後者で判定する。
- **頻度**：変更のたびに CI で回す。正答率が前の版より下がる変更は入れない。
- **失敗の記録**：zenz が辞書を悪くした例と、良くした例を両方とも残し、規則の見直しに使う。

### 速さ

- 打鍵の列を再生して、打鍵の表示、Space の応答、zenz の応答の分布を測る。速い打鍵者の打鍵間隔も再生する。
- 差し替えが効いた割合（利用者の次の操作より前に差し替わった割合）を測る。
