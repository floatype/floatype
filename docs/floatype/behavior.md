# floatype の動き

floatype が打鍵から確定までに何をするかを、時間の順に書く。仕様（何を作るか、なぜ）は [spec.md](spec.md) にある。ここに書く数字は既定値で、どれも設定ファイル（`~/.config/floatype/config.toml`、8 章）か設定画面（F の印の項目）で変えられる。括弧の中は設定の名前。

## 1. 打ってから確定するまで

「きょうはいいてんき」とローマ字で打ち、手を止め、Enter で確定する場合。

| 時刻 | 起きること | 画面 | インジケータ |
|---|---|---|---|
| 1 文字目 | かなが未確定の文字になる。予測候補の窓が出る。止まっていた zenz を別のスレッドで起こす（後述） | きょ | 入力中 |
| 2 文字目以降 | 読みが 2 文字（`live_conversion_min_chars`）に達し、ライブ変換が受け持つ | きょうは… | Mozc |
| 打つたびに | 前のライブ変換の結果を見せたまま、後ろに打ったかなを足す。予測候補を作り直す | 今日はいいて | Mozc |
| 最後のキーから 228ms（`live_conversion_delay_millisec`） | 手が止まったとみなし、読み全体を Mozc で変換し直す（ライブ変換）。zenz に聞く予約をする | 今日はいい天気 | Zenz… |
| 最後のキーから 500ms（`zenz_delay_millisec`） | zenz に読みと直前の文（最大 40 文字）を送る | 今日はいい天気 | Zenz… |
| その約 26ms 後（中央値、M4 Pro。90% は 77ms 以内） | zenz の答えが届く。下の「zenz の答えの扱い」で採るか決める | 採れば zenz の答え | 採れば Zenz、採らなければ Mozc |
| Enter | 見えているものを確定する | | 消える |

- 手を止めずに打ち続けている間は、ライブ変換も zenz も動かない。どちらも「最後のキーから」数える。
- 手を止めるたびに読み全体を変換し直す（Mozkey と同じ）。前に zenz が直した部分も、いったん Mozc の結果に戻り、zenz が答えるとまた直る。
- zenz の答えを 300ms（`zenz_timeout_millisec`）待っても来なければ捨て、Mozc の結果のままにする。
- 待つ間に別のキーを打つと、その依頼は取り消す（届いた答えも捨てる）。
- zenz に渡す直前の文からは、個人情報らしい並びを外す。URL、メールアドレス、ファイルのパス、鍵やトークンらしい長い英数字、長い数字（電話番号、カード番号、口座番号）があれば、最後のそれより後ろだけを渡す（メールはtaro@example.comです なら です だけ）。直前の文がそれで終わっていれば、何も渡さない。
- アプリが直前の文を教えないとき（ターミナルなど）は、同じ行で直前に確定した文節（Mozc の履歴文節、最大 4 つ）を代わりに渡す（`zenz_context_from_commits`、既定オン。設定画面の「一般」ページの zenz の枠で切れる）。アプリの種類は見分けていない。
  - Enter や矢印など、アプリに渡るキーを打つと Mozc が履歴文節を捨てるので、行を変えたあとは渡らない。フォーカスが移ったときも同じ。
  - セキュア入力（パスワード欄、ターミナルの「キーボード入力のセキュリティを保護」）の間に確定した文字が履歴文節に残っているあいだは、渡さない（2026-11-21 に直した。それまでは、セキュア入力を切ったあとに渡りえた）。
  - 効き目（2026-11-21 の計測）：同じ行で続きの文を打つと当たりやすくなる（説明書の文などから作った 68 組で、渡さない 42 → 渡す 49）。関係のない文を同じ行に続けて確定すると外れやすくなる（1,745 文で 1,234 → 1,171、2,000 文で 1,482 → 1,423）。得失が分かれるので設定にしてある。
  - 渡すもの：日付（2026/11/20、2026-11-20）、版の番号（v1.2.3）、短い番号（1eb3a62d9、100-0001）、普通の英単語。
  - zenz は手元で動くので、もともと外には出ていない。使い道の無いものを手元の採点プロセスにも渡さないための決まり。
  - 見分けられないもの：全角の数字の長い並びと、アプリから取った 20 文字の切れ目で途中から始まった並び（鍵の後ろ半分など）。

### Space で変換するとき

- Space を押すとすぐ Mozc で変換し、同時に zenz に聞く（予約の待ちはない）。インジケータは Zenz… になり、答えで Zenz か Mozc に変わる。
- もう一度 Space で次の候補、候補の窓から選べる。
- zenz の補正の表示中に Space を押すと Mozc の結果に戻る（Mozkey と同じ。候補の窓はまだ開かない。ライブ変換の表示中なら、ライブ変換のまま）。次の Space からは Mozc の候補を Mozc の順に出す（完治に戻った後 で Space を 1 回押すと 感じに戻ったあと、2 回で 漢字に戻ったあと、3 回で 幹事に戻ったあと）。
  - 退けた zenz の候補は、Mozc が付けた元の順位に戻る。2026-11-20 までは 2 番目に置いていて、Space を 2 回押すと退けたはずの候補がまた出た。
  - 同じ日に一度、「最初の Space は補正を選んだまま候補の窓を開く」動きにしたが、利用者と相談して Mozkey と同じに戻した。
- 日英混在入力がオンで、入力が英単語で終わっているときは、変換せずに確定して半角の空白を入れる（6 章。`mixed_english_space_commits` でオフにできる）。

### zenz の答えの扱い

届いた答えは、次のどれかに当てはまれば捨てて Mozc の結果のままにする。

- 長さの上限で途中で止まった
- 読みをかなのまま返した。ただし、前に文があり、答えが全部ひらがなで、Mozc の結果が読み全体に対する辞書の 1 語でないときは採用する（そうなの の なの は 名の にしない、いただけますと の けますと は 毛マスト にしない）。カタカナで返した答え（馬運車 に バウンシャ）と、辞書の 1 語を開いた答え（計算 に けいさん）は捨てる
- 利用者が打った数字や英字（読みに入っている 2026、gpt-5 など）を、Mozc の結果にあるのに変えた
- Mozc の候補を組み合わせて書けず、文節を区切り直しても書けず、辞書の語で読みを確かめることもできない（下の「Mozc の文節のままでは書けない答え」）
- Mozc と同じだった

捨てなければ、各文節の候補を zenz の答えに合わせて並べ替えて見せる（Zenz）。数字や記号の全角・半角は Mozc の書き方を残す。

Mozc の文節のままでは書けない答えは、文節を区切り直して Mozc にもう一度変換させてから書く（Zenzai が zenz の答えに沿って変換し直すのに当たる）。

- 自分の候補で答えのその部分を書ける文節は、そのまま残す。
- 漢数字の候補を持つ文節が並び、その漢数字をつなげた数が答えのその部分の数字と同じなら（線|九百|七|重|二 の 千九百七十二 と 1972）、一つの文節にまとめ、その数字を候補に足す。Mozc は数の読みを細かく区切ると算用数字で書けず、一つにまとめて変換し直しても かな しか出さないため。数字の全角・半角は、その文節で Mozc が出す数字の候補に合わせる（１０００ が先なら １９７２）。
- 残りの書けない文節の並びは、一つの文節にまとめる（もく|ろん（木|論）を もくろん にすると 目論ん が候補にある）。1 文節だけなら区切りの位置がずれているので、後ろの文節（最後なら前の文節）と合わせる。
- それでも書けなければ、zenz の答えの区切りで切り直す。答えのかなを読みに当てはめ、ひらがなの後に漢字やカタカナが始まる位置で切る（がかんせいど|たかい を が|かんせいどたかい にすると 完成度高い が候補にある。つくえ|にものを|おく は つくえに|ものを|おく にして 机に|物を|置く）。出すのは Mozc の辞書の候補だけ。
- 答えの数字は、読みのその部分を数として読んだ値と同じときだけ当てはめる（せんきゅうひゃくきゅうじゅういち と 1991、じゅうはっ（さい）と 18、ごじゅっ（しゅうねん）と 50。100 未満は英語読みも読む：ふぁいぶ と 5、ふぃふてぃー と 50）。当てはまった数は一つの文節にして、その数字を候補に足す。数字の全角・半角は設定（「数字の入力」）に従う。読みと合わない数字（はちじかん に 0時間）を書いた答えは、この切り直しでは書けない。
- zenz の区切りだけで書けなければ、Mozc の元の区切りも重ねて切る（が|かんせいど|たかい）。数の文節は割らない。
- それでも Mozc の候補で書けなければ、zenz の書いた文字をそのまま候補に足して見せる。ただし、答えを端から端まで「辞書の語（読みと表記の組）、かな、打ったままの字、数として読める数字、名前で読める英字（じぇーあーる と JR、ぶい と V）」で読みどおりに読めるときだけ（ふちゅうしゃ の 不忠者 は 不忠 と 者、ちとせはつはねだゆき の 千歳発羽田行き は 千歳・発・羽田・行き）。英数字の間のハイフンは読まないものとして通す（えっくすふぁいぶ の X-5、びーにじゅうきゅう の B-29）。読めない答え（はちにち に 纂日）は見せない。切るのは語と語の間だけで、ひらがなの後に別の文字が始まる位置。
  - Mozc が漢字で書いたところを かな に開いた答えは、この形では見せない（方から を かたから、出現場所 を つげんばしょ。zenz がその語を知らないことが多い）。答えのひらがなの数が Mozc の結果より多いかで見る。
- Mozc が読み全体を辞書の 1 語で書いたときは、どの切り直しもしない（ひともうけ の 一儲け を 人も受け に、にようそにんしょう の 二要素認証 を に要素認証 にしない）。その文節の別の候補を選ぶ補正はする。かなのままの結果（もうこんなじかん）は 1 語と見なさない。
- 利用者の学習で先頭になった候補を持つ文節でも、zenz は別の候補を選べる（間違えて覚えさせた 完治 を、zenz が前後の文から 漢字 に直す）。2026-11-20 までは、そういう文節を zenz は変えられなかった。
  - ただし、学習が押しのけた Mozc の 1 位には戻さない（機会 が 1 位の きかい で 機械 を選んで覚えさせたら、zenz は 機会 を出さない）。同じ表記の候補が複数あっても、どれも使わない。この決まりと下の「区切り直さない」は、「zenz が直した語を Mozc にも覚えさせる」がオンのあいだは外す。
  - 利用者が退けた語を書く答えは捨てる（下の「確定の前後の操作」）。
- 利用者の学習で先頭になった候補を持つ文節は区切り直さない（zenz の区切りでの切り直しと、zenz の文字を足すことは、そういう文節が一つでもあればしない）。
- 区切り直した変換の表示中に Space を押すと、Mozc の元の区切りと結果に戻る。zenz の候補は元の区切りには無いので、続く Space では Mozc の候補を順に出す。
- 区切り直しは Mozc に学習させない（確定しても、文節の区切りも候補の順も覚えない）。

### zenz が直した語を Mozc にも覚えさせる（オフが既定）

設定画面の「入力補助」ページの「zenz のメモリと学習」にある「zenz が直した語を、確定したら変換の順位にも覚えさせる」（`zenz_teaches_mozc`）で切り替える。オンは、Mozkey の既定（確定した Zenz 補正を Mozc の変換履歴に追加学習する）に当たる。

- オフ（既定）：zenz の補正をそのまま確定しても、Mozc の変換の順位は変わらない。次に同じ語を打つと、Mozc は元の結果を出し、zenz が前後の文を見て直す。
- オン：zenz が変えた語を、候補を手で選んだときと同じ強さで Mozc が覚える。次からは zenz を待たずにその語が出る。
  - 覚えた語は前後の文を見ずに出る。完治に戻った後 を確定したあとの かんじをかく は、Space の直後に確定すると 完治を書く になる（オフなら Mozc の 感じを書く）。zenz の答えを待てば、どちらも 漢字を書く。
  - そのため、オンのあいだは「学習が押しのけた Mozc の 1 位には戻さない」「学習で先頭になった候補を持つ文節は区切り直さない」（上の「zenz の答えの扱い」）の決まりを外し、履歴で先頭になった語も zenz が直せるようにする。Mozc の履歴では、zenz が覚えさせた語と手で選んだ語を見分けられないため。Mozkey が zenz から守るのもユーザー辞書の語、数字、固有名詞で、履歴で先頭になった候補は入っていない（公開されているソースで確かめた範囲）。
  - 手で選び直した語は、オンでも「退けた語」の記録が守る（選び直したときに先頭にあった語と、zenz が出していた語を、zenz は書かない。下の「確定の前後の操作」）。記録の無いもの（2026-11-20 より前に覚えた語、`zenz_learning` がオフのあいだに選んだ語）は守られず、zenz が直すことがある。
  - 覚えさせるのは、Mozc の文節のまま書けた補正の、zenz が変えた文節だけ。文節を区切り直した補正は、オンでも覚えさせない（Mozkey は、zenz が変えた語の単位を、文節の区切りを確かめてから覚える）。
- 既定をオフにしている理由（2026-11-24 に測り直した。#24）：AJIMEE の拡張版 628 問を、1 問ずつ確定して学習を次の問題へ持ち越して比べた。zenz が直したあとに残る文の正解は、オンもオフも 481 で同じ。zenz が直す前（Space の直後）は、オフ 270、オン 269 で、オンだけ正しいものが 19（努めた → 務めた など）、オンだけ誤りが 20（使えていた機能 → 仕えていた昨日、全体工程 → 全体皇帝 など）。Mozc の学習は語ごとで隣の文節くらいしか見ないので、zenz が文脈で選んだ語が別の文に出る。
  - 覚えさせた語は Mozc の履歴に入り、「学習データを見る…」の一覧には出ない。消すには、その語を変換して control+delete を押す。確定の直後の Backspace は、その確定で覚えた分を戻す。シークレットモードでは覚えない。
- 計測（2026-11-21。文を順に打ち、学習を次の文へ持ち越す。オフ → オン）：最後に出る結果の正解は 628 問で 466 → 466、1,745 問で 1,234 → 1,233。Space の直後の正解は 269 → 267、1,097 → 1,065。同じ語があまり繰り返されない文の集まりなので、よく使う語を何度も打つ人の得は入っていない。

### 選び直した語を、どの言い回しでも先に出す（オフが既定）

設定画面の「辞書」ページの「学習」にある「選び直した語を、どの言い回しでも先に出す」（`learn_chosen_words_everywhere`）で切り替える（#28、#10）。

- Mozc は、選び直した語を文脈ごとに覚える（隣の文節も見て覚える）。文脈を問わずに覚えるのは、選んだ語の品詞の組が、もとの 1 位と同じときだけ。
  - 登録していない よい を「〜とよい」で選んでも、ほかの言い回しでは 良い のまま。Space で出る よい は形容詞の非自立で、1 位の 良い（形容詞の自立）と組が違うため。
  - 形容詞として単語登録した よい は、1 回選ぶとどの言い回しでも よい になる。11-22 に「登録した語は広がる」と見えたのはこれで、名詞として登録すると広がらない。登録したことではなく、品詞の組で決まる。
- オンにすると、組が違っても文脈を問わずに覚える。「はしるとよい」で 1 回 よい を選ぶと、確認すると・移動すると・修正すると・続行して・比べたほうが・書いても のあとと、それは よいことだ が、どれも よい になる（2026-11-24、実物の辞書で zenz なし。オフでは 7 つとも 良い のまま）。ほう／方 と 機会／機械 の結果は、オンでもオフでも同じだった。
- 害：漢字の選び直しも広がる。病気の話で 1 回 完治 を選ぶと、ほかの文の かんじ も 完治 寄りになる。戻すには、その語を変換して control+delete を押す（Mozc が覚えた順を忘れる）。
- 1 文字の語は、オンでも広がらない（Mozc がもとから文脈つきでしか覚えない）。
- オンにする前に選んだ語には効かない（その時は文脈つきでしか覚えていない）。
- 決まりを一言にするため、かなの語だけに絞らなかった（利用者と決めた）。1 語だけ決めたいときは、候補の固定（control+shift+P、#28）を使う。

### 確定の前後の操作

| 操作 | 動き |
|---|---|
| 入力中に Ctrl+z（ことえり配列） | 変換して、その場で zenz に聞く（手動の補正） |
| 変換の表示中に Ctrl+z | 「これではない」。見えている変換（zenz の補正でも Mozc の結果でも）を外して zenz に次の候補を聞き、Mozc の候補で書けて見た目が変わるものを出す。押すたびに次へ進む |
| 補正の表示中に control+delete（fn を足しても同じ） | その補正を止めて Mozc の結果に戻し、同じ読みでは二度としない（`zenz_learning`） |
| 確定の直後の Backspace、Ctrl+Backspace | 確定で覚えたことを戻す（文字はアプリが消す） |
| 変換の表示中に control+delete（zenz の補正が出ていないとき。ことえり配列） | 見ている文節で Mozc が覚えた候補の順を忘れ、入力中に戻る（Mozc にもともとある機能）。間違えて覚えさせた候補はこれで消せる（かんじ を変換して 完治 が出たら control+delete）。zenz の補正が出ているときは、1 回目で補正を止め、2 回目でこれが働く |
| zenz の補正をそのまま確定 | 覚えて、次に同じ読みでは zenz を待たずにすぐ出す（すぐ出す読みの長さは設定できる。下の「覚えた補正をすぐ出す読みの長さ」） |
| 補正を Space で Mozc の結果に戻して確定 | zenz が変えていた語を数える。選び直した文節の語は 1 回で、そのまま確定したときは 2 回目で「退けた語」になり、zenz はその語を書く答えを出さなくなる |
| 先頭の候補を別の候補に選び直して確定 | 先頭にあった語を「退けた語」として覚える |
| 変換の表示中に control+shift+P（ことえり配列） | 選んでいる候補を、その読みの「固定した語」にする。固定した語にもう一度押すと外す（下の「候補の固定」） |

退けた語は次のように扱う。

- 覚えるのは語の読みと表記（完治に を 漢字に に選び直したら、かんじ と 完治）。助詞などは含めないので、別の文でも効く（かんじにもどった で退けたら、かんじをかく でも zenz は 完治 を出さない）。
- 補正を Space で戻したあと、別の候補を自分で選んで確定したら、選び直した文節で zenz が書いていた語を 1 回で退ける（完治に戻った後 → Space → Space で 漢字に → Enter で、かんじ と 完治）。選び直していない文節の語は数えない（同じ補正の 後 は退けない）。zenz の語そのものを選び直したときも退けない。
- Space で戻した Mozc の結果をそのまま確定したら（Space → Enter）、zenz が変えていた語を「1 回退けた語」として控え、同じ語で 2 回目に退ける。Space の押し間違い 1 回では止めないため（2026-11-20 に利用者が選んだ）。あいだにその語の入った補正をそのまま確定したら、数え直す。
- Space のあとに打ち続けたときは数えない（確定されるのは別の変換なので）。区切り直した補正を戻したときも数えない。
- 補正が出ていないときに先頭の候補を選び直したら、先頭にあった Mozc の語を覚える。
- 覚えるのは、その確定で Mozc も学習するときだけ（シークレットモード、学習なしの設定、`zenz_learning` がオフのときは覚えない）。
- シークレットモードと、Mozc の学習を止めているとき（履歴を読むだけ、履歴なし）は、zenz のほかの記録も書かない：そのまま確定した補正（すぐ出す補正）も、control+delete で止めた補正も覚えない（止めた補正は、その場では止まる）。前に覚えた「すぐ出す補正」も、シークレットモードと「履歴なし」の間は zenz の答えより先には出さない（Mozc が自分の履歴を使わないのと同じ。「履歴を読むだけ」のときは出す）。前に止めた補正と退けた語は、シークレットモードでも出さない。2026-11-21 に直した（それまでは、すぐ出す補正と止めた補正がシークレットモードでも記録されていた）。
- この決まりの代わりに起きること：zenz が間違えていて Mozc の結果でよかったとき（Space → Enter）は、その間違いがもう 1 回出る。正しい補正を Space → Enter で 2 回流すと、その語は自分で一度選んで確定するまで zenz が出さなくなる。
- zenz の答えが退けた語を 1 つでも使うなら、その答えは全部捨てて Mozc の結果のままにする。覚えてすぐ出す補正（上の表）も同じ。
- 退けた語を自分で選んで確定すると忘れる。先頭に出たものをそのまま確定しただけでは忘れない。
- 確定の直後の Backspace と Ctrl+Backspace は、その確定で覚えたことと忘れたことを戻す。
- 1,000 語まで覚え、古いものから忘れる。保存先はプロファイルの `floatype_zenz_turned_down.tsv`（退けた語）と `floatype_zenz_refused_once.tsv`（1 回退けた語）。入力履歴を消すと一緒に消える。
- 最初の文節だけの確定（MS-IME 配列の Ctrl+↓ など）でも覚える。先頭からフォーカスのある文節までの確定と、文節の長さを変えたあとにそれより前で選んでいた分は覚えない。
- Mozkey は、補正の採用と却下を「読み全体と補正の文字列」ごとに数えて、却下が多い補正を出さなくする（既定は読み 7 文字以上）。Floatype は語ごとに覚える。文ごとだと、同じ間違いが別の文でまた出るため（2026-11-20、利用者に任されて決めた）。その代わり、文脈で書き分けたい語（感じ と 漢字）でも、退けた側を zenz は出せなくなる。

覚えた補正をすぐ出す読みの長さは、設定で変えられる（`zenz_remembered_min_chars`。設定画面の「入力補助」ページの「zenz のメモリと学習」。既定は 1 で、いつもすぐ出す。Mozkey の既定は 7）。

- 短い読みは、文によって書き分けたい語が多い。どちらが良いかは場面で分かれる。2026-11-21 に実物のモデルで、2 回目を Space の直後に確定して比べた（「覚えさせる」は上の `zenz_teaches_mozc`）。

### 候補の固定（#28）

- 変換の候補か予測候補を選んで control+shift+P を押すと、その語の読みと表記（さいとう と 齋藤）を固定する。候補の語のすぐ右に、赤いピンのアイコン（macOS の SF Symbols の pin.fill）が出る（変換プロセスは説明の頭に 📌 を付けて知らせ、候補の窓がそれをアイコンに替える。利用者が「固定」の文字よりアイコンを選んだ）。予測候補で固定しても、先頭に置くのは変換の候補だけで、予測候補の並びは変えない（言い回しの続きの順を崩さないため）。設定「固定した語を、予測候補でも先頭に出す」（`pinned_words_in_predictions`、既定オフ。設定画面の「サジェスト」ページ）をオンにすると、予測候補でも先頭に出す。出すのは、その語の読みを打ち終えたときの、その語だけ（さいとう まで打てば 齋藤。さい の途中や 齋藤さん は動かさない）。どちらも 2026-11-24 に利用者と決めた。以後、その読みの語が出る文節では、Mozc の候補の先頭に置く。学習で覚えた順より先。
- zenz は、固定した語の文節を書き換えない。補正のほかの文節はそのまま直す。zenz が文節を区切り直した答えでは、固定した語が残らない答えを捨てる。覚えてすぐ出す補正（上の表）も同じ。
- 1 つの読みに固定できるのは 1 語。別の語を固定すると、前の語は外れる。
- 効くのは、候補の窓を開いて候補を選んでいるときだけ。ライブ変換や zenz の補正が出ているだけのとき（窓を開く前）と、カタカナ・英字などの文字種の候補では何もしない。確定した文節（文節を移って決めたもの）は、区切り直しても固定した語に戻さない。
- 効くのは、Mozc がその語を候補に出した文節だけ。読みが別の文節に分かれたときは効かない。語の単位なので、ほかの語とひとまとまりになった中では効かない：ほう を固定しても、くらべたほうが の ほう は くらべた の一部なので、zenz が 比べた方が と書くのは止められない。
- 実物の辞書で確かめた（2026-11-24、zenz なし）：よい を固定すると、走ると・確認すると・移動すると・修正すると・続行して・比べたほうが・書いても・やったほうが のあとの 良い と、良いことだ が、どれも よい になった。ほう を固定すると、この方です・あの方に が ほうです・ほうに になった。
- 文脈で書き分けたい語（齋藤 と 斉藤）でも、固定した語がいつも先頭に出る。外すには、もう一度 control+shift+P を押すか、「学習データを見る…」で消す。
- zenz の設定や学習の設定に関係なく効く。シークレットモードでも効く。入力履歴を消しても消えない（ユーザー辞書と同じ扱い）。保存先はプロファイルの `floatype_pinned.tsv`（1 行に 読み、タブ、表記）。
- ことえり配列にだけ入れてある。自分で作ったキー設定の表では、「候補を固定する／外す」（`PinSelectedCandidate`）を足す。
- 別の IME（Windows 用）の「固定ピン」を見て、利用者が入れることにした（2026-11-24）。zenz が表記を書き換える件（#10）は、これで直す。

覚えた内容は、見て消せる。

- 設定画面の「入力補助」ページの「zenz のメモリと学習」にある「学習データを見る…」で一覧が開く。種類は 退けた語、1 回退けた語、すぐ出す補正、止めた補正、固定した語。読みか表記で絞り込み、選んだ行か全部を消せる（全部を消しても、固定した語は残る）。
- 覚えた内容は、プロファイルにある 5 つのテキストファイル（`floatype_zenz_*.tsv` と `floatype_pinned.tsv`。1 行に 読み、タブ、表記）が正で、画面はその行を消すだけ。「Finder で表示」で場所が開く。手で書き換えてもよい。
- 変換のほうは、ファイルが変わっていたら読み直す（見るのは 1 秒に 1 回まで。書く前は必ず見る）。消した内容は 1 秒ほどあとの変換から効く。
- Mozc が覚えた候補の順は、この画面には出ない（一覧にできない形で保存されている）。1 つずつ消すには、その語を変換して control+delete を押す（上の表）。

変換の表示中の Ctrl+z は次のように動く。

- 外すのは、押したときに見えていた変換と、同じ読みと前の文脈で zenz が答えたのに出せなかった答え（Mozc と同じだった、Mozc の候補で書けなかったなど）。全角と半角の違いだけの答えは同じものとみなす。
- zenz は一番の答えが外されていれば、その答えの中で二番手との差が一番小さい所を一つだけ二番手に変え、続きをいつもどおり書く。それも外されていれば次に差が小さい所を試す（最大 8 か所）。乱数は使わないので、同じ状況なら同じ順に出る。
- 届いた答えが出せないものなら、外すものに加えて聞き直す（1 回の押下で最大 8 回）。
- 次の候補が Mozc の結果なら、それを出す（インジケータは Mozc に戻る）。この後の Space は Mozc の結果のまま次の候補へ進む。
- 出せるものが残っていないか、300ms（`zenz_timeout_millisec`、自動の補正と同じ）を過ぎたら、見えているものをそのまま残す。
- 外したものは、読みか前の文脈が変わるか、新しい変換で zenz に聞き直すと忘れる。
- Space で Mozc の結果に戻しただけでは外したことにならない。その後の Ctrl+z では zenz の補正がもう一度出る。

## 3. 予測候補と変換候補

- 打っている途中に、番号なしの小さな一覧（予測候補）を出す。Mozc の辞書の語と、入力の履歴から出す。
- 足した辞書（人名、地名、SudachiDict、ニコニコ大百科と pixiv 百科事典の語）の語は、最後まで打って変換すれば出るが、既定では予測候補に出さない。数文字打ったところに知られていない語が出るのを防ぐため（たあと → 田蛙澄）。ニコニコと pixiv の両方にある語（草生える など）は予測候補にも出す。
  - `suggest_added_words`（設定画面の「予測候補」）をオンにすると、足した語も予測候補に出す（Mozkey と同じ）。予測候補と、予測候補に混ぜる途中までの変換の両方に効く。
- 手を止めてライブ変換が動いたあとも、予測候補の窓を残す（Mozkey と同じ）。zenz が補正しても残る。手を止める直前に出ていた一覧をそのまま残すので、直前に出ていなければ出ない。
- 予測候補はクリックで選べる。Tab か ↓ で一覧に入り、番号や矢印で選んで Enter で確定する。数字キーをそのまま打つと読みに入る（手を止めたあとに数字を打てるように。Mozkey も同じ）。
- 予測候補を選んで確定すると、変換の順位もその語を覚える（Mozkey の同じ機能に当たる。2026-11-21。切り替えは無い。Mozkey は確かめられた文節だけを覚え、Floatype は文全体が書けるときだけ覚える）。それまでは、選んだ文が予測候補に出やすくなるだけで、変換の順位は変わらなかった。
  - 例（実物の辞書）：zenz が直した 漢字を書く を一度確定し、次に かんじを まで打って予測候補の 漢字を書く を選ぶ。そのあとの かんじ は、Space の直後から 漢字 になる（選ばなければ 感じ）。
  - 覚えさせるのは、選んだ候補の読み全体を Mozc が変換し直し、その文節の候補をつないで同じ文字列が書けるときだけ。先頭でない候補を選ぶことになる文節があれば、手で選んだときと同じ強さで覚える。全角と半角の違いも同じとは見なさない。
  - 覚えさせないとき：Mozc の変換の先頭がもうその文字列のとき（教えることが無い）、Mozc の候補では書けないとき（zenz だけが書いた 百千年 など。推測では覚えない）、途中までの確定、学習しない印の付いた候補（日付など）、シークレットモードと学習を止めているとき。
  - クリック、Tab や ↓ で入って Enter、番号、ライブ変換のあとの一覧のどれで選んでも同じ。確定の直後の Backspace と Ctrl+Backspace は、この学習も戻す。
  - 選んだ文が押しのけた Mozc の語は「退けた語」には入れない（利用者がその語を見て退けたわけではないため）。既定では、学習が押しのけた語に戻さない決まりが守る。「zenz が直した語を Mozc にも覚えさせる」がオンのときはその決まりを外すので、zenz が別の文で直すことがある。
- Space を押すと変換する。変換候補の窓（番号つき）は、もう一度 Space を押して次の候補へ進んだときに出る（Mozc と同じ）。
- 予測候補（打っている途中に出る窓）には下の帯を付けない（Mozkey と同じ）。予測候補の一覧と変換候補には「1 / 9」の帯を付ける。設定 `candidate_kind_mark` をオンにすると、帯の左に丸を描いて見分けられる（予測候補の一覧は青、変換候補は灰色）。0.1.10 から既定はオフ（利用者の求め。0.1.9 は公開していない）。選んでいる候補が自分の入力履歴から出たものなら、帯に「⌃⌫ で履歴から削除」と出す（Mac のキー記号で短く。0.1.9 まで「control+deleteで履歴から削除」）。丸の色は、変換候補と予測候補の一覧のそれぞれで選べる（`candidate_style` と `suggest_style` の `kind_mark_color`。設定画面の「外観」ページで、丸を出すときに色の行が出る）。
- 用例のある候補は、行の右端に小さなオレンジの丸を付ける（Mozc と Mozkey は棒で、スクロールのつまみと紛らわしいため）。その行を選ぶと横に用例の窓が出る。
- 数字は、打った数字も変換した数字も半角にする（Mozc と Mozkey は「打つと全角、変換は前回の形」）。漢数字や桁区切り（1,000）などの書き方は前に選んだものを覚え、幅だけを半角にする。設定画面の「一般」の「数字の入力」（半角／全角／全角（変換は前回の形））か、「入力補助」の「半角・全角」の「編集…」で開く表の数字の行で変えられる。どちらも同じ設定で、選択肢にない組み合わせを表で選ぶと「表で個別に設定」と出る。表を変えていない設定ファイルには新しい既定が効く。
- 英字と、数字や英字の横のピリオド・カンマも、打っている最中から半角にする（2026-11-21。利用者：「全角で打ちたいタイミングなんてない、変換できればそれでいい」）。v1.2.3 は打ち始めから v1.2.3、update は うpだて と見えて、手を止めると update。日本語の 。、 は別の規則なので変わらない。全角にしたいときは、設定画面の「入力補助」の全角・半角の表で「アルファベット」「ピリオド・カンマ」を変える。F9 などで全角英数に変換する操作は今までどおり。全角英数の入力モードで打った英字は全角のまま。
  - 仕組み：日英混在の判定は「ローマ字の残りの英字は全角、英単語として残した英字は半角」という幅の違いを合図にしている。そこで変換プロセスの内側では英字を全角のまま扱い、アプリに渡す直前（入力中の文字と、その確定）で半角に書き換える。変換の候補は書き換えない。

## 4. zenz の採点プロセス

- zenz（zenz-v3.2-small）は別のプロセス（`floatype_scorer`）で動く。CPU だけを使い、ネットワークに触れない。
- 変換と候補の窓のプロセスは、macOS に操作に応える役（`ProcessType` が `Interactive`）として登録している。CPU が混んでいても、キーの処理と描画がふつうのアプリと同じ優先度で動く。採点プロセスは変換プロセスの優先度を受け継ぐ。utility に下げると省電力のコアに回され、補正が中央値 39 → 52ms、90% 101 → 152ms と遅くなったのでやめた（Mozc と Mozkey は登録しておらず、変換と候補の窓もふつうのアプリより低い優先度で動く。azooKey は zenz も含めて入力メソッドの本体 1 つのプロセスで動く）。
- 1 分間依頼が無ければ自分で終わり、メモリを返す（`zenz_stop_when_idle`）。次に打った 1 文字目で、キーの処理とは別のスレッドで起こす。モデルの読み込みは約 10ms で、手を止めて zenz に聞くまでの約 0.5 秒に間に合う。キーは待たない。
- 動いている間のメモリ（アクティビティモニタの「メモリ」）は約 30MB（M4 Pro での値）。
  - llama.cpp は、重みを CPU の速い計算向けに並べ替えた複製（約 67MB）を使う。この複製は、ビルドのときに作って同梱したファイル（`zenz-v3.2-small-Q5_K_M.repacked`）を対応づけて読むので、プロセスが自分のメモリに持たない。起動のたびに並べ替えることもしない。
  - 対応づけたファイルの分は「メモリ」には数えられないが、使っている間は macOS のファイルのキャッシュに載る。実際に載っている量（RSS）は約 166MB で、メモリの中で並べ替えていた前の作り（約 169MB）と変わらない。足りなくなれば macOS が捨てて、読み直せる分。
  - 答えと速さは前の作りと同じ（同じ重みを同じ計算で使う。4 つの評価 4,573 問で答えの差は 0）。
  - このファイルが無い、欠けている、別のモデルから作ったものだと分かったときは使わず、前の作りと同じくメモリの中で並べ替える（約 96MB になる）。
- 動いている間の floatype 全体は約 72MB（2026-11-20 に、入れ直したアプリで打っている最中に測った。本体 10・候補の窓 17・変換 17・採点プロセス 28。実際に載っている量は、採点プロセスだけで約 164MB）。
- 止まっているときの floatype 全体は約 39MB（本体 10・候補の窓 17・変換 12）。候補の窓は、出した候補の数で 17〜32MB の間を動く。

## 5. 句読点で確定する（オフが既定）

`use_direct_commit` をオンにすると、`direct_commit_characters`（既定 、。？！「」）を打ったところで、入力中の文を変換して zenz の答えを待ち（最大 300ms）、そのまま確定する。待っている間の Enter はその場で確定、ほかのキーは見えているものを確定してから効く。

## 6. そのほかの入力の動き（英数字の後の / のほかは、どれもオフが既定）

- 英数字の後の /（`slash_after_ascii`、既定オン）：かなの入力で、英字や数字のすぐ後に打った / は、中黒（・）ではなく半角の / のまま入る（2026/11/20。日英混在入力がオンなら before/after、test/spec、src/ も）。変換しても確定しても / のまま。ローマ字入力のときだけで、かな入力ではそのキーのかな（め）が入る。
  - 「すぐ後」とは：入力中なら、キャレットの直前が、打ったままの英字か数字、英単語として拾える語（日英混在入力がオンのとき。まだ かな と英字の混ざった てst でもよい）、ローマ字の残りが 2 字以上続くところ（src）。何も入力していないときは、アプリが教える直前の文字が英数字のとき。アプリが教えないとき（ターミナルなど）は、直前のキーで確定した文字列の末尾が英数字のとき（確定のあとに別のキーを打ったら数えない）。変換中に / を打ったときは、それで確定する文字列の末尾で見る。
  - かなの後や行の頭の / は、今までどおり記号の設定に従う（既定は ・）。z/ はいつも ・。英数入力のときは関係しない。

- 日英混在入力（`mixed_english`）：かなの入力中に打った英単語を、変換で英字（半角）のままにする。英単語とみなすのは、ローマ字がかなにならずに英字が残り、英単語の一覧にある 3 文字以上の語。一覧は、SCOWL（一般の英語の約 8 万 8 千語）、初めから足してある語（json、config、page、time など。8 章）、自分で足した語（8 章の `english_words.txt`）を合わせたもの。
  - 次の 3 つの動きは、1 つずつオフにできる（2026-11-21。どれも既定はオン。設定画面の「一般」ページの「入力の補助」で、日英混在入力のすぐ下。日英混在入力がオフのあいだは押せない）。
    - `mixed_english_space_commits`：英単語のあとの Space で、変換せずに確定して半角の空白を入れる。オフにすると、Space は Mozc と同じく変換する（update + Space で update が変換として出て、Enter で確定する。空白は入らない）。空白で区切って英語を続けて打つ動き（meet you、git commit -m）は、これがオンのときだけ。
    - `mixed_english_enter_commits`：英単語のあと、手を止める前に Enter を押しても英字で確定する。オフにすると、画面に出ているとおりに確定する（うpだて）。
    - `mixed_english_leading_symbols`：かなが 1 つも無い入力の、頭の記号を打ったとおりにする（/review、--help、@src/app.ts）。オフにすると、頭の記号は記号の設定に従う（・review、ーーhelp、＠src/app.ts）。語の間の記号（config.toml、src/main）は変わらない。空白で区切って英語を打っているときの引数（git commit のあとの -m、--help のあとに Space）は、オフでも打ったとおり。
  - 空白で区切って打つ英文（nice to meet you）は扱わない。最初の語が日本語として確定されるので、偽とmeet you になる。英文は、英数キーで macOS の ABC に切り替えて打つ。確定した語をあとから英字に書き直す試作（`mixed_english_rewrite`）は、2026-11-21 に実機で試してやめ、設定ごと消した。ターミナルでは動いたが、純正のメモと TextEdit では二重になった（偽とnice to meet you）。先に確定してから置き換える形に作り直したが、確定した文字があとから書き換わる動きそのものを利用者が望まず、やめた。空白で区切って英語を続ける動き（英単語のあとの Space で確定し、次の語も英字で続く。meet you、git commit -m）は、そのまま残る。日本語を 1 語ずつ変換する打ち方で 俺python が ore python になる害もあった。
  - 文の途中でも単語ごとに見る。「きょうは update する」は 今日はupdateする、「update を」は updateを になる。
  - 手を止めた（ライブ変換）か変換したときに、その語を打ったとおりの英字に置き換える。そのあと打つかなは、英字のあとに かな で続く。
  - Backspace（2026-11-22 に変えた）：英単語のあとの かな を消すあいだは、英単語は英字のまま残る（updateを → update）。英単語の字を消すときは 1 回で 1 字。残りが英単語なら英字のまま（takes → take、sits → sit）、英単語でなければ打ったキーの かな に戻る（update → うpだt）。どちらでも、続けて打つキーは かな として続く（take + wo → takeを、sit + agaki → したがき。sit の t のようにローマ字の途中の字が残る語は、次の英字のキーで打ったキーに戻る）。前は、英字を 1 字消したあとに打つキーがすべて英字のままになった（sits、Backspace、agaki が sitagaki。take、wo が takewo。Mozc が、英字のモードで打った字の隣では英字のモードを続けるため）。効くのは、小文字・数字・ー のキーだけで打った入力の末尾。大文字や記号を打った入力では、前のままの動き（英字が 1 字消え、英字のモードが続く）。Delete と矢印キーは直していない。
  - 英単語の最後の子音が次のかなとつながったときも拾う（test + する は てsつる、email + を は えまいlwお と出るが、testする、emailを になる）。
  - 音の途中で手を止めたとき（きょうは + s が has と読める）は、英字で見せるが、次に英字のキーを打つと打ったとおりに戻す（きょうはしる）。子音で終わる英単語（email、keyboard）も同じで、続けて を を打つと emailを になる。
    - これで起きること（ちらつき）：日本語を打っていて、子音を打った直後に手を止めると、そこまでの綴りがたまたま英単語のとき、英字が一瞬出る（のいらい の のいr で noir、はいれつ の はいr で hair）。続きを打てば戻り、確定する文字は変わらない。日本語 4,633 文で数えると、かな 1 文字ごとに手を止めた場合に英字が出るのは 107 回・25 文（機能オフで 55 回・8 文）、キー 1 つごとに手を止めた場合は 13,307 回・4,047 文（オフで 113 回・13 文）。2026-11-20 と 11-21 の版で同じ。
    - 控えめにする案（子音で終わっているあいだは英字にしない）は入れていない。git や test のような、子音で終わる英単語まで、確定するまで ぎｔ のように見えてしまうため。見分けるには新しい判定が要る。
  - 手を止める前に Enter を押しても、英単語は英字で確定する（update のあとすぐ Enter で update。2026-11-21 までは、画面のとおり うｐだて が確定されていた）。手を止めたら出るはずだった形で確定する。日本語は、変換されていなければ かな のまま確定する。
    - かなが 1 つもできなかった入力（英字だけの kwsk や w、英字に数字や記号の付いた v1.2.3 や x86_64）も、打ったとおりの半角で確定する。手を止めたときと同じ形になる。
    - 手を止めたときと違いが残るもの：かなの横に残った英字は、手を止める前だと全角のまま（ok は おｋ、手を止めれば おk）。数字と記号だけのもの（192.168.0.1）は、手を止める前だと設定どおりの幅のまま。日本語は、手を止める前だと変換されない（a4 は あ4、手を止めれば 亜4）。
    - 英語だけの項目で測ると（手を止めずに Enter）、単語の開発用 44 件で直す前 1 件 → 43 件（手を止めた場合と同じ）、確認用 23 件中 23、打鍵の開発用 75 件中 63、確認用 36 件中 25（どれも手を止めた場合と同じ数）。日本語だけの 12,167 入力と 3,000 文で、これで新しく英字になった確定は無い（英字が出るのは、手を止めた場合と同じ 2 件）。
  - ローマ字が全部かなになる語（before は べふぉれ、hello は へっぉ、open は おぺん）は、その語だけで打ったとき（入力の頭から終わりまで、または / などの記号で区切られたところ）に、そのかなが日本語として読めなければ英字にする。日本語として読めるかは、「2 文字以上の辞書の語」と「1 文字の助詞（は、が、ね など）」だけで端から端まで読めるかで見る。まで（made）、して（site）、たけ（take）、わね（wane）は日本語のまま。
  - 初めから足してある語と、`english_words.txt` に自分で足した語は、その語だけで打ったときは、かなが日本語として読めても英字にする（page は ぱげ、time は ちめ で、どちらもたまたま辞書に語があるが、page、time になる）。「して」と読める site のような語を足すと、その読みが日本語として打てなくなる。英字になったあと F6 を押すと、ひらがなに戻る。
  - かなに続けて打った、全部かなになる語も拾う（filewohozonsita は ふぃぇをほぞんした と出るが、fileを保存した になる。onlineで参加します、ここでsaveしてください）。決め方は次のとおり。
    - かなの並びが日本語として読めるなら、何もしない。ここでは「2 拍以上の辞書の語」「かな 1 字に ゃ ゅ ょ が付いた辞書の語（しょ、ちゃ）」「1 文字の助詞・語尾・語幹（は、た、い、し など）」で端から端まで読めるかで見る。入力の終わりは、打っている途中の語でもよい（それはべ の べ は べんり などの書き出し）。
    - 読めないときだけ、英単語をいちばん少ない数だけ使って、残りのかながすべて日本語として読める分け方を探す。同じ数なら長い語を取る（おんぃねで は お + ん + line ではなく online）。そういう分け方が無ければ、何もしない。
    - 語の最後の子音が次のかなとつながっていても拾う（event + を は えゔぇんとぉ と出るが、eventを になる。bugを も同じ）。
    - 英字のすぐ隣には拾わない（英単語が空白なしで続くことはない）。まだ かな になっていない英字（打っている途中の子音）の隣のかなも、そのままにする。
    - 入力の終わりで拾った語は、続けて英字のキーを打つと かな に戻る（それはbefore のあとに に を打つと それはべふぉれに。次に手を止めたとき、また拾う）。後ろにかながある語は、そのまま英字で残る。
    - 英単語の一覧の語かどうかと、残りが日本語として読めるかだけで決める。前後の文の意味は見ない。
  - かなが 1 文字ずつなら日本語として読めてしまう語も、変換の点数で見分ける（sizeが大きすぎる、imageを添付します、それはbeforeと同じです。初めから足してある語と自分で足した語なら timeを記録する、dataを保存する、noteにまとめる）。
    - その語を英字にして変換したときと、かなのまま変換したときの、Mozc の変換の点数を比べる。英字にしたほうが十分に安ければ英字にする。「し + ぜ + が」のように、1 文字ずつなら読めるが文としては不自然な並びが当たる。
    - 初めから足してある語と自分で足した語は、差が小さめでも英字にする。一般の英単語は、4 文字以上で、かなが辞書の語でないものを、差が大きいときだけ英字にする（しぜ、べふぉれ は辞書に無い。まけ、それ、まに は辞書の語なので見ない）。
    - 日本語として自然な並びは変えない（負けを認める、ここで待つ、その手のもの、猫の手も借りたい）。
    - 打っている途中は決めきらない。手を止めると英字で見せるが、続けて英字のキーを打つと かな に戻し、次に手を止めたときに、増えた分も含めて見直す（真人間のそれにち で止めると sore に見えることがあるが、近づいてきた まで打てば それ に戻る）。打っている途中の語が、その語のかなの途中から始まるかもしれないときは、英字で見せない（じょうとのてつづ は 譲渡の手続き に続く）。ただし、語の後ろがもう日本語として読めるときは点数で決める（ちめを は time + を。め + を で始まる語が辞書にあっても、time が出たり消えたりしない）。
    - 日本語の続きで打ち始めた入力の頭が、助詞（は が を に で と も の など）で始まる語は見ない（猫 のあとの のてをみる は の手を見る。座布団 のあとの にねを は に根を）。助詞で始まらない語は見る（今日は のあとの ちめをきろくする は timeを記録する）。前が日本語かどうかは、アプリが知らせる前の文字で決める。知らせないとき（ターミナル、1,000 文字を超える文書、空の文書）は、直前のキーで Floatype が確定した文字で決める。それも無ければ（改行や矢印のあと、使い始め）、文の頭として扱う。
    - かなの並び 1 つにつき 1 語まで。
  - 手を止めて英字になったあと、続けて英字のキーを打つと、打ったとおりの かな に戻して続ける（base になった ばせ に い を打つと ばせい）。全部かなになる語のあとは、伸ばす棒（ー）のキーでも かな に戻る（note になった のて に ー を打つと のてー。「のテーマ」と打てる）。記号や / を打ったときは英字のまま。
  - 英単語のあとの Space は、変換ではなく、確定して半角の空白を入れる。英語を単語ごとに、切り替えなしで打てる（time is money、git push origin main）。
    - 入力が英単語で終わっているときに効く。前に日本語があれば、日本語を変換し、zenz の答えを待ってから（次のキーが先ならその時点で）全部を確定して空白を入れる（これはpull のあとの Space で「これはpull 」）。
    - かなが 1 つも無い入力では、語のあとの . , ! ? ; : も打ったとおり半角で確定する（thank you. と hello, world）。日本語のあとの記号で終わる入力（これはtest。）は、今までどおり変換する。
    - 日本語として読める語は、今までどおり変換する（made は まで、are は あれ、tomato は トマト）。
    - Shift で英字を打ったあと（英数の入力に切り替わっている間）の Space は Mozc のままで、入力の中に空白が入る。
    - 取り消し（Ctrl+Backspace）は、空白も含めて消して入力中に戻す。
    - 英単語の候補（大文字、全角）を見たいときは、Space の前に F10 を押す。ひらがなに戻すのは F6。変換に別のキーがあるキー設定（MS-IME と ATOK の 変換キー、Shift+Space）では、そのキーで今までどおり変換できる。
    - Space のあとにすぐ Enter を打つと、確定は済んでいるので、Enter はアプリに届く（改行や送信になる）。
  - 英語が続いている間は、次の語も英語として読む。
    - Space で英単語を確定した直後に打ち始めた入力が、頭から終わりまで 1 つの英単語なら、かなが日本語として読めても英字にする（how are you の are と you、this is a pen の a と pen）。3 文字以上は英単語の一覧の語。1〜2 文字は a、i、am、an、as、at、be、by、do、go、he、hi、if、in、is、it、me、my、no、of、oh、ok、on、or、so、to、up、us、we。
    - - で始まる英数字も打ったとおりにする（git commit -m、ls -la）。
    - 1 つの英単語でない入力は、日本語として変換する（git push してください、no problem です）。このときは文の頭として変換し、直前の英単語を前の語として扱わない（Mozc は「英字 + 空白 1 つ」の後ろを前の語の続きとして変換するので、push のあとの に が 二 になることがある）。
    - 続きが終わるのは、ほかの確定をしたとき（日本語の確定、Enter での確定）と、何も入力していないところで文字以外のキーを打ったとき（矢印、Backspace、Enter、2 つ目の Space）。クリックで場所を変えたときも終わる（アプリが知らせるキャレットの前が「語と空白」でなくなる。前の文字を知らせないアプリでは、次のキーまで分からない）。
    - 日本語にも英語にも読める 1 語は、ここでは英語になる（git push のあとに site だけを打つと、して にならない）。
  - Space を打ったときだけ英語とみなすものがある。英字が残る 1〜2 文字の語（of は おf、it は いt、is は いs）と、かなが 1 つもできなかった入力（ls、cd、npm、src）。手を止めただけでは変えない（いt は いった の途中かもしれない）。
  - 記号でつないだ名前は、記号も打ったとおり半角にする（config.toml、foo_bar、@src/app.ts、key=value、localhost:3000、--help、$skill）。
    - 対象は、英字のあいだか英字の前にある . _ / @ : = - $ # + & * % ^ \ | ~ < > と数字。文の中でもよい（今日はconfig.tomlを開く）。
    - かなが 1 つも無い入力では、頭の記号も打ったとおりにする（/review、--help）。入力の頭の / を ・ にしたいときは z/ と打つ。
    - 入力の終わりの記号（test。）と、かっこ（「file」）は日本語のまま。
  - 記号の隣が英語なら、日本語として読める部分も英字にする。
    - 英単語の一覧の語（node_modules の node、src/main.rs の main）。ただし . の隣の語は、2 つの文かもしれないので変えない（それ。test、test。それ）。伸ばす棒（ー）の前の語も変えない（era-log は エラーlog）。数字だけの隣も変えない（3。して）。
    - . のあとのファイルやホストの終わり（cc、ts、rs、md、json、html、com、jp など）と、その前の語（main.cc）。
    - @ の前（taro@example.com の taro）。
    - 英字が残っていて、後ろに続きがある部分（usr/local/bin の usr）。
    - 1 文字ずつを記号でつないだもの（a.b.c）。
  - 空白なしで続けて打った英語も英字にする（timeismoney、helloworld、goodmorning、pullrequest）。
    - 入力の全部が 2 つ以上の英単語に分けられ、しかも日本語として読めない部分が残るときだけ。英単語は 3 文字以上で、is、it、of などの 2 文字の語は、かなにならない英字が途中にある入力でだけ使う。
    - かなだけになった入力（英字が 1 つも残らず、ほかの決まりで拾った英単語も無い）は、キーが英単語の並びに見えても日本語のまま（をたべてた は wot + abet + eta ではない）。
    - 文の中でも、拾った英単語 2 つのあいだのかなが日本語として読めないときは、つなげて 1 語にする（pullれquestをおくる は pull + れ + quest ではなく pullrequestを送る）。あいだが日本語として読めるときはそのまま（pushしてmergeする、fileをdeleteする）。
    - 英単語の隣が日本語として読めるなら、日本語のまま（pushして、あとでtest、fileの）。そのため thankyou（thank + よう）、letsgo（lets + ご）、noproblem（の + problem）、takecare（たけ + かれ）、usecase は英語にならない。
  - Shift で打った大文字の前でも語を拾う（camelCase の camel、userId の user）。Shift のあとは英数の入力になり、ふつうは手を止めても変換しないが、前に英単語があるときだけ英字に直す。
  - 英単語の切り方。隣のかなが日本語として読める切り方を先に選ぶ（きょうはてsとぉかきます は 今日は + test + を書きます。hates + とぉ ではない）。t のあとの s は し（shi）の一部として読む（commitします、testします。commits + ひます ではない）。
  - 拾えないもの：
    - かなが普通の日本語の語になる語を、かなに続けて打ったとき。site（して）、make（まけ）、name（なめ）、home（ほめ）、more（もれ）、take（たけ）、date（だて）など。mode（もで）も、点数の差が足りず拾えない。これらの語は、その語だけで打つか、/ などの記号で区切れば英字になる（初めから足してある語と自分で足した語のとき）。
    - ん の直後の、母音で始まる語（かんたん + update は かんたぬpだて）。
    - 助詞のかなとつながって別の英単語になる場合（あとで + test は あと + detest と読める）。
    - 最初の語が日本語として読める英文（nice to meet you の nice は にせ、no problem の no は の、make sure の make は まけ）。最初の Space で日本語として変換される。
    - Shift で大文字を打った語の前が、全部かなになる語のとき（fileName は ふぃぇName のまま）。
  - `mixed_english_in_indicator`（既定オフ。設定画面では日英混在入力の下の「インジケータの右端に、いまの語が日本語か英字かを出す」）をオンにすると、インジケータの右端に、キャレットの直前の語が英字なら A、それ以外は あ を出す。
- 曖昧なローマ字の途中表示（`display_ambiguous_romaji`）：長い規則の途中のローマ字を、いまの時点の かな で見せる（n は ん）。
- 末尾の ww（設定なし、2026-11-22 に変えた）：入力の最後の ww は、手を止めても Space で変換しても、見えているとおり ww のまま（すごいww、草ww）。Mozc は「っ」だけにしていた（すごいっ）。ローマ字の表の ww は「っ と w」で、www の規則（w の連続を打つためのもの）があるので ww の時点ではまだ決まらず、決まらない字を変換に渡すときに残りの w を落としていた。Mozc の合成部（`composer/char_chunk.cc`）を直したので、残りの字がある規則で、もっと長い規則があるものはみな、決まるまで打ったとおりに渡る（Mac で使うローマ字とかなの表では ww だけ。自分で作ったローマ字の表に同じ形の規則があれば、それにも効く）。ww のあとに別の子音を打てば、今までどおり っ になる（すごいwwです は すごいっwです）。
- ライブ変換のルビ（`live_conversion_ruby`）：ライブ変換の上に読みを小さく出す。
- zenz を待ってから表示（`live_conversion_waits_for_zenz_millisec`）：手を止めたとき、Mozc の結果を先に出さず、zenz の答えを最大この時間待ってから 1 度だけ出す。

### 入力ソースは 1 つ

macOS に届ける入力ソースは「Floatype」の 1 つだけ（名前は 2026-11-21 に「ひらがな (Floatype)」から変えた。1 つしか無いので「ひらがな」は要らない）（2026-11-21 に 5 つから 2 つに、同じ日に 1 つに減らした）。英字は macOS の ABC で打つ：英数キーを押すと macOS が ABC に切り替え、かなキーで Floatype に戻る。利用者は azooKey でも Mozkey でも、ひらがなだけを足して英数は ABC を使っていて、Floatype の「英数」は一度も使われていなかった。メニューバーのアイコンは F だけ。

- 「カタカナ」「半角カナ」「全角英数」の入力モードは、メニューバーと入力ソースの一覧からは選べなくなった。前に足してあった場合は、入れ直したあと一覧から消えるはず（実機では未確認）。
- カタカナや全角英数に変換する操作（F7、F8、F9 など）は今までどおり使える。
- キー設定でこの 3 つのモードへ切り替えるコマンドを割り当てている場合、切り替えは今までどおり働く。メニューバーのアイコンは「ひらがな」のまま変わらない。ひらがなへ戻すには、かなキーか、同じコマンドを使う。
- 「ひらがな」は、ID も名前も変えていない。前に足した「ひらがな (Floatype)」はそのまま使える。「英数 (Floatype)」を足していた場合は、入れ直したあと一覧から消えるはず。
- キー設定で Floatype の中の英数（直接入力、半角英数）に切り替えた場合、メニューバーのアイコンは変わらない。かなキーでひらがなに戻る。
- 実機では未確認：英数キーで ABC に切り替わること（これまでは、足していない「英数 (Floatype)」を選ぶよう macOS に頼んでいて、その結果として ABC になっていた可能性がある）。

### 更新の確認

設定画面の「その他」ページの「更新を確認」を押すと、GitHub の Releases に新しい版があるかを見に行く（2026-11-21）。Floatype が外と通信するのは、このボタンを押したときだけ。起動時や定期の確認はしない。打った文字や設定は送らない（送るのは「最新のリリースを教えて」という問い合わせだけ）。

- 出る言葉は 4 つ：「最新です」「新しい版 X があります」「まだリリースがありません」「確認できませんでした」。
- 新しい版があるときは、ボタンが「ダウンロードして入れる」に変わる。押すと、pkg とその SHA-256 のファイルを一時フォルダに取ってきて、SHA-256 が合えば macOS のインストーラで開き、設定画面を閉じる。合わなければ消して知らせる。入れるかどうかは、インストーラの画面で決める。
- 取ってくるのは `https://github.com/floatype/floatype/releases/download/` で始まる場所だけ。https 以外と、ほかの場所を指す応答は使わない。
- SHA-256 が示すのは、取ってきた物が Releases に置かれた物と同じで壊れていないことまで。pkg に署名と公証が付くまでは、それ以上は確かめられない。
- 通信は設定画面のプロセスが macOS の curl を呼んで行う。変換、入力メソッドの本体、採点プロセスには通信のコードが無いままで、`floatype/eval/local_only.py` が、確認先の文字列を持つ実行ファイルが 1 つだけであることを見る。

## 8. 設定の置き場所

- 設定は `~/.config/floatype/config.toml` の 1 か所にある。Mozc の項目も floatype の項目もここに書く。書式は TOML で、キーは `config.proto` の項目名。書かない項目は既定値。例は floatype.app の `Resources/config.example.toml`。
- 設定画面は、項目を変えたその場で、変えた項目の行だけをこのファイルに書き込む（色や大きさは、手を止めて 0.4 秒ほど後）。書く前にファイルを読み直し、その上に変えた項目だけを当てるので、手で直したほかの項目は残る。コメントと順番も残る。既定値に戻した項目は行を消し、新しい項目はその表の最後の項目の後に足す。書き込むときは、項目もコメントも無くなった `[表の名前]` の行を消し、続いた空行は 1 行にまとめ、ファイルの頭と終わりの空行も消す（複数行の値の中の空行はそのまま）。全部を既定値に戻すと、ファイルは空になる。
- 手で書き換えると、保存して 1 秒ほど後に打った次のキーで反映する。
- 設定画面を開いたまま手で書き換えると、画面にも反映する（2026-11-24）。画面は、2 つのファイルのあるフォルダ（シンボリックリンクならリンク先のフォルダも）を FSEvents で見張り、知らせが来たら `config.toml` と `english_words.txt` の更新時刻・大きさ・inode を見比べる。0.3 秒後にもう一度見て変わっていなければ読み直す（書きかけを読まないため）。置き換えて保存するエディタも、その場で書くエディタも拾う。知らせの取りこぼしとリンクの張り替えに備えて、2 秒ごとにも見比べる。
  - 画面で変えてまだ書いていない色や大きさは、画面の値を残す。ファイルでも同じ項目が変わっていたら、ファイルの値にして、画面にそう出す。
  - ローマ字表、キー設定、文字の幅の窓は、開いたときの表を下書きにして、「保存」で表を丸ごと書く。開いている間に同じ表を手で直すと、後から保存したほうが残る。
- `config.toml` が dotfiles の管理などで別の場所へのシンボリックリンクなら、リンクのまま残し、リンク先のファイルを書き換える。
- 誤りがある（TOML として読めない、項目名や型が違う、値が範囲の外）と、行番号を通知で知らせ、直前の正しい設定のまま動く。直すまで、設定画面の変更はファイルに書き込まず、効きもしない（通知で知らせる）。
- `config1.db`（Mozc の設定の保存先）は、最後に読めた設定の写しになる。ファイルが壊れたまま floatype を起動し直したときは、これを使う。
- ファイルが無いとき（初めて起動したときなど）は、`config1.db` と、前の版の設定ファイル `~/.config/floatype/config.txtpb`（あれば）を合わせて、既定と違う項目だけを書いたファイルを作る。`config1.db` と `config.txtpb` は消さない。

### ユーザー辞書

- 単語登録と辞書ツールの語は `~/.config/floatype/user_dictionary.tsv` の 1 ファイルにある（Mozc の `user_dictionary.db` の代わり）。手で書き換えてよい。
- 書式は辞書ツールの書き出しと同じで、よみ、単語、品詞、コメントをタブで区切った行（コメントは無くてよい）。品詞は辞書ツールに出る名前（名詞、固有名詞、短縮よみ、抑制単語 など）。辞書ごとに `[辞書名]` の行で始める。`#` で始まる行と空行は読み飛ばす。

  ```
  # 仕事の語
  [ユーザー辞書 1]
  ふろーと	floatype	固有名詞	入力ソフト
  ```

- よみが `#` で始まる語は、行が読み飛ばされないよう全角の `＃` で書く（変換では同じに扱う）。辞書ツールで取り込んだ語の言語（`名詞:en` の `en`）も残る。
- 辞書ツールと単語登録は、保存するときにファイル全体を書き直す。残るのは、ファイルの頭と終わりのコメントと空行、それに行の直前のコメントと空行（その行が残っていれば、同じ行の前に）。消した語の前にあったコメントは消える。辞書ツールで辞書の名前を変えると、その辞書の `[辞書名]` の行の前と、中のコメントも消える。辞書と辞書の間には空行を入れ、改行は LF に、先頭の BOM は外れる。変換に使われない語（よみか単語が空の行など）は書かない。
- 手で書き換えると、保存して 1 秒ほど後に打った次のキーで変換に効く（入力の学習を保存してから読み直す）。
- シンボリックリンクなら、リンクのまま残し、リンク先のファイルを書き換える。
- 誤りがある（区切りが足りない、品詞の名前が違う、`[辞書名]` の行より前に語がある、辞書名が重なる、辞書が 100 個か 1 つの辞書の語が 100 万語を超える など）と、行番号を通知で知らせ、変換は直前に読めた語のまま動く。直すまで、辞書ツールと単語登録はファイルに書き込まない（通知で知らせる）。壊れたまま floatype を起動し直したときは、直すまでユーザー辞書の語は出ない。
- 辞書ツールを開いたあとにファイルを手で書き換えると、そのツールでの変更は保存しない（通知で知らせる。開き直せば、書き換えたファイルから始まる）。
- ファイルが無いときは、Mozc の `user_dictionary.db`（あれば）から作る。`user_dictionary.db` は消さず、その後は読まない。`user_dictionary.tsv` を消すと、次に読むときに `user_dictionary.db` からまた作る（語を全部消したいときは、ファイルを空にする）。

### 英単語

- 日英混在入力で英単語とみなす語を、`~/.config/floatype/english_words.txt` で足したり外したりできる。1 行に 1 語で、大文字と小文字は区別しない。`#` で始まる行と空行は読み飛ばす。
  - 語をそのまま書くと、足す。ここに足した語は、その語だけで打ったとき、ローマ字が全部かなになる綴りでも、いつも英字にする（6 章）。
  - 頭に `-` を付けて書くと、外す（`-time`）。初めから足してある語にも、SCOWL の語にも効く。外した語は英単語として拾わない。
  - 設定画面の「一般」ページの「入力の補助」にある「英単語を編集…」でも足したり外したりできる。一覧には、ファイルの語と、初めから足してある語が並ぶ（SCOWL の語は多すぎるので出さない）。画面はファイルの行だけを書き換え、手で書いたコメントと空行は残す。開いたあとにファイルが手で書き換えられていたら、書き込まずに読み直して知らせる。
- 初めから足してある語が 166 語ある（ソースの `src/floatype/english/preset_words.txt`）。自分で足した語と同じ扱いで、ファイルが無くても効く。
  - かなが辞書で読めてしまうが、その語だけを日本語として打つことがまず無い語（62 語）：page、menu、data、time、code、token、video、note、main、idea、area、redo、safe、zone、wide、guide、pane、core、case、cache、icon、encode、unicode、secure、notice、queue、require、unique、cookie、sequence、delete、device、voice、native、move、save、remove、invite、engine、origin、resize、hidden、domain、define、session、feature、issue、route、remote、separate、position、message、join、region、wifi、azure、debian、apache、ubuntu、heroku、notion、openai。
  - 小文字で書くことの多いソフトウェアの語（ほとんどは SCOWL に無い）：json、yaml、toml、config、env、npm、async、auth、backend、frontend、localhost、readme、webhook、gitlab、figma、vscode、xcode、mozc、zenz、dev、utf など 94 語。
  - アポストロフィを省いて打つ語（10 語）：arent、didnt、doesnt、dont、havent、isnt、thats、wasnt、whats、youre。
  - 入れていない語：かなを日本語として打つことがある語（site は して、made は まで、node は ので、home は ほめ、name は なめ、date は だて、demo は でも、memo は めも）。かなの続きによくある日本語がある語（mode は もでる、todo は とどく、undo は うんどう、mute は むてんか、gate は がてら。その語のかなで手を止めると、日本語を打っている途中でも英字が出てしまう）。API、URL のように大文字で書く略語（Shift を押しながら打てば、そのまま英字になる）。入れたい語は `english_words.txt` に 1 行書けば足せる。
  - 初めから足してある語でも、かなの続きに日本語があるものは残っている（time は ちめ で、地名 の途中。note は のて で、「の手」「の天気」の途中）。そこで手を止めると英字が出るが、続けて英字のキーか ー を打てば かな に戻る。気になる語は `-time` のように外せる。
- 使えるのは英字だけの 3〜32 文字の語（それより短い語や記号の入った語は英単語として拾えない）。ほかの行は使わず、行番号を通知で知らせる。残りの語は使う。
- ファイルが無いときは、SCOWL の一覧と初めから足してある語を使う。
- 手で書き換えると、保存して 1 秒ほど後に打った次のキーで効く。
